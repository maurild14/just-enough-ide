# Security and privacy

> Purpose: what JEI does and never does with your data, and the hygiene rules for contributors · Status: current · Last reviewed: 2026-10-20

Source: `PRD.md` §9. To report a vulnerability, follow `SECURITY.md`.

New Claude Search operations reject unresolved double-slash project roots before source or process access. Canonical filesystem metadata must prove rooted Windows drive/native UNC or single-leading-slash POSIX grammar; a backslash in a POSIX component is insufficient. See ADR 0021.

Shared Files previews validate both the lexical relative path and the target/root realpaths with `nativeRel(..., host.platform)` before reading. POSIX literal-backslash targets and case-distinct double-slash siblings cannot alias an in-root slash/UNC path. This applies to Quick Open previews as well as ordinary Files and cross-tab line targets; legacy path-helper defaults remain unchanged.

## Privacy model

- JEI is local. It sends nothing over the network itself.
- The only model calls are the ones the user starts: generating a commit message, and Ask. They go through the user's own host session and provider.
- `git fetch`, `pull` and `push` talk to the user's own remotes, and only on a user action. JEI never fetches in the background.
- JEI stores per-project UI state through the host's own session storage, including Search results and replacement snapshots. Search/replacement retention is bounded per operation (ADR 0023); host copies and retained roots add overhead.

## Safe behavior

On OpenCode, sensitive-file approval covers the exact list shown and crosses RPC as `approvedSensitive: string[]`. After each approval the TUI requests another fresh plan; any newly sensitive path requires a new confirmation. The server independently replans and refuses before any Git steps unless every current sensitive path is included in that exact approved list. Comparison preserves literal whitespace and case. On refusal the TUI shows the full current list and requires approval before one retry; cancel stops the commit. The busy guard remains held throughout. See `docs/decisions/0010-exact-sensitive-path-approval.md`.

- **Secrets never go to the model.** Generating a commit message sends the diff without the contents of any file that looks sensitive (the same `sensitive.ts` rules, on either side of a rename): such a file appears by name only, as `<path>: sensitive file, contents omitted` (`omitSensitive` in `core/git/diff.ts`).
- **Conflicts are never committed.** While any file is unmerged, `commitPlan` returns no steps and the refusal `Resolve conflicts first.`; both hosts show it and run nothing (a smart commit's `add -A` would otherwise mark conflict markers resolved). The OpenCode server refuses the commit RPC the same way.
- **Open never runs a file.** With `editorCommand` empty, `o` uses the OS opener, which runs anything it treats as a program; JEI refuses runnable types first (`openRefusal` in `core/files/open.ts`: `.exe`, `.bat`, `.cmd`, `.ps1`, `.vbs`, `.js`, `.lnk`, `.msi`, `.hta`, `.jar`, `.sh`, `.command`, `.app`, `.desktop`, `.appimage` and more, case-insensitive) with `Set editorCommand to open this file type.` It is a denylist: a set `editorCommand` opens any type. The path goes to the opener in the platform's own form (backslashes on Windows) on both hosts.
- **Secrets in commits.** Before a smart commit stages everything, paths that look sensitive (`core/git/sensitive.ts`) are listed and the user must confirm with "Commit anyway". Matching is on the basename, case-insensitive: `.env`, `.env.*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa*`, `id_ed25519*`, `credentials.json`, `.npmrc`, `.netrc`. The committed templates `.env.example`, `.env.sample` and `.env.template` are not flagged. Both hosts implement the confirmation; OpenCode passes the exact `approvedSensitive` list, and its server enforces coverage against a fresh plan before executing.
- **Destructive actions** (discard, discard all, delete, checkout over local changes) always confirm. Core switching/creation also confirms dirty changes or leaving detached HEAD, and checkout/revert always confirms. Fresh service validation precedes every execution, including confirmed retries. JEI never stashes or forces a switch and never discards changes to make it succeed. Merge reverts are refused in the service.
- **Refs are literal.** Branch creation uses `check-ref-format --branch` and rejects expanded shorthand; switching/creation also refuses the single `@` name that Git expands as HEAD. Existing targets must match an exact full branch ref or a unique listed short name; comparisons resolve them to full hashes, excluding tags and revision expressions. Commit actions accept only existing full lowercase 40-hex commit hashes. `--end-of-options` separates revisions from options; `--` separates literal diff paths.
- **Web URLs and Git errors omit credentials.** Commit links support GitHub/GitLab remotes and reconstruct HTTPS URLs without userinfo. URL openers accept HTTPS without userinfo only. Git errors redact URL userinfo, including malformed whitespace-bearing values, in the display line, stored stderr and copied argv, while execution keeps its original arguments. The upstream remote of HEAD is preferred, else `origin`; unsupported or unavailable remotes produce no link. See ADR 0013.
- **No surprise permission dialogs.** Claude Code shell-tool permissions are checked with `$.tool.check` first; the pane explains the normal host review path. A query creates no classifier verdict. Sync's verified missing-review refusal stops execution and offers a prompt draft only, without retries, hook bypass or relaxed permissions (ADR 0018).
- **No shell strings.** Every process is an argv array, which also removes a whole class of injection through file names.
- **Search ignores executable configuration.** Content search begins `rg --json --no-config`, uses an explicit `.` directory and passes the pattern only as `-e <pattern>`. Quick Open's files-mode exception is `rg --files --no-config --null`, because JSON mode does not list files. Include/exclude values remain individual arguments. Git grep alone enables generated glob/exclude pathspecs with `GIT_LITERAL_PATHSPECS=0`; it retains every other fixed Git environment setting and never accepts arbitrary pathspec magic as an option.
- **Replace checks every whole-file write.** Shared planning and apply resolve literal paths and real paths inside the project, preserve CRLF, reject NUL/binary or invalid UTF-8 anywhere in the complete file, and refuse files changed since preview. Files over 4 MiB and unreadable files have explicit skip reasons. Literal replacement edits only exact text including case; case-different matches are omitted with `case-differs` without discarding eligible edits in the same file. Internal regex replacement refuses a file when JS cannot fully match any supplied engine substring. Fallback exposes and replaces only the first verified occurrence per line, never an invented range. The host confirms the reviewed file/all plan; apply still revalidates before writing. The Host has no atomic compare-and-swap for a concurrent external write after the final check.
- **Incomplete replacement reviews are refused.** Search accepts at most 2,000 lines and an estimated 16 MiB of retained strings/ranges; replacement retains an estimated 32 MiB of reviewed before/after strings. Truncation or an oversized review requires narrowing, and never returns a partial replacement plan. Empty literal replacement queries and multiline Search patterns are refused. Unicode whole-word boundaries are rechecked independently before planning (ADR 0023).
- **Search filenames retain native identity.** `nativeRel` uses the host platform for content search, Quick Open and replacement, including resolved paths. POSIX colon names remain literal; POSIX backslash paths are unsupported and omitted by searches/lists, while a direct replacement returns `unsupported-path`. They never become slash-path counterparts. Windows separator/drive containment remains unchanged. Zero-width Git matches require complete successful paired output and first-match verification; truncation or a semantic mismatch cannot authorize an inferred write (ADR 0020).
- **Paths stay inside the project root.** Every path JEI writes or deletes is resolved and checked. The Files service refuses a relative path that leaves the root (listing and preview return empty) and a preview whose real path (after symlinks) is outside the root's real path. Git runs with `GIT_LITERAL_PATHSPECS=1`, so a file name with `[`, `*` or `?` never matches other files when staged, restored or cleaned.
- **No lock contention.** Git runs with `--no-optional-locks` so JEI never blocks the agent.

## Repository hygiene

- No secrets, tokens, personal paths, usernames, emails or real project names in code, fixtures, docs or screenshots. Fixtures use `acme-app` and fictional authors (`@example.com`).
- Commits use the maintainer's GitHub noreply identity, never a personal address. The license names "The JEI contributors".
- CI runs a gitleaks scan on the full history (`.gitleaksignore` lists one fingerprint: the fictional file names in `core/git/sensitive.spec.ts` line 9, which also carries `// gitleaks:allow`), with `contents: read` permissions, `persist-credentials: false` on checkout, and Dependabot keeping the SHA-pinned actions current; run a secret scan over the repo before each release.
- npm publishing runs from GitHub Actions through npm trusted publishing (OIDC): no npm token exists to leak, and provenance is attached automatically. `.github/workflows/release.yml` runs release-please (`contents`, `issues` and `pull-requests: write`, nothing else) and a `publish` job in the `npm` environment with only `contents: read` and `id-token: write`; it runs the tests before `npm publish` and installs nothing unpinned (Node 24's bundled npm already supports trusted publishing). Actions are pinned by commit SHA and run with least-privilege `permissions`. The trusted publisher on npmjs.com (this repository, `release.yml`, environment `npm`) is a one-time maintainer setup described in `CONTRIBUTING.md`.
- `.claude-plugin/types/` (laid by Claude Code) is gitignored and never committed.

## Reporting

Report vulnerabilities privately as described in `SECURITY.md`; do not open a public issue for them.
