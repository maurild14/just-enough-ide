# JEI v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship JEI 0.3 on Claude Code and OpenCode. It adds the Search tab (ripgrep streaming, send to the agent, replace with preview), Quick Open inside Search, and the Symbols tab: outline, workspace search, definition, references, call hierarchy and send to the agent. Symbols are approximate everywhere; on Claude Code they use the LSP tool when it is allowed.

**Architecture:** As in 0.1 and 0.2.
- `core/search/` and `core/symbols/` hold every parser, ranking, argv and planning function as pure code, plus thin `Host`-based services.
- `Host` gains streaming (`stream`) and writing (`writeText`). The adapters implement them: Claude Code with `$.process.spawn` and `$.fs.write`; OpenCode with `node:child_process` and `node:fs` in the server entry, pushing streamed results to the TUI over RPC events.
- Each host draws the two tabs. Preview from any tab reuses the 0.1 Files preview.

**Tech Stack:** Unchanged (TypeScript, Bun, `claude plugin test`, `@opencode/plugin` 2.0.32, `@opentui/solid` 0.5.17, zero runtime dependencies). `rg` (ripgrep) is an optional runtime tool on the user's PATH.

**Spec:** `PRD.md` §6.2 (Search, Quick Open), §6.3 (Symbols), §5.3 (handing text to the agent), §9 (privacy), §11 (0.3 row). Docs: `docs/architecture.md`, `docs/design.md`, `docs/hosts.md`, `docs/conventions.md`, `docs/security.md`, and every ADR under `docs/decisions/` (notably 0009 Esc on Claude Code and 0010 exact approvals).

## Global Constraints

- Everything in the 0.1 and 0.2 plans' Global Constraints still applies:
  - English only, and no personal data (fixtures use `acme-app`, Ana Rivera and Leo Park `@example.com`).
  - `core/` stays pure, and its code uses ECMAScript built-ins only (no `TextEncoder`, `Buffer` or `node:*`).
  - argv only. Keys are defined only in `core/keys.ts`.
  - Destructive actions confirm. Every feature lands on both hosts or neither.
  - Every view fits 24/40/80/120 columns and short panes (5 rows), and survives a live resize.
- Every `rg` call starts `['rg', '--json', '--no-config', ...]`. The pattern is always passed as `-e <pattern>` (or `--files` mode), never as a bare positional, so a leading `-` cannot become an option.
- Every path a search returns, writes or previews must resolve inside the project root (`isInside`/`projectRel`). A write refuses anything else.
- Limits:
  - Search: cap 2,000 matches with `Results truncated.`; debounce 150 ms; cancel the previous run on each new query.
  - Text to the agent: cap 12,000 characters, adding `…and N more.`
  - Quick Open list: cap 50,000 paths.
- Replace writes UTF-8 text only. A file that is binary, is not valid UTF-8, or changed since the preview is skipped and listed under `Not replaced` with the reason.
- Symbol data always says where it came from. List headers end with ` · LSP` or ` · approximate`.
- JEI never triggers a host permission dialog by surprise. LSP use is gated by `$.tool.check`, as PRD §6.3 says.

## Review Focus

1. **Unicode and byte offsets.** `rg --json` reports byte offsets into UTF-8 lines. With `ñ`, emoji, or CJK before the match, highlights and replacements must land on the right characters. Test: Task 1 `byteToIndex` and the replace specs.
2. **Hostile or odd queries and filenames.** A query of `-rf`, `--pre=x`, `(`, or an empty regex; a glob of `!**`; file names with spaces, `:` or newlines; CRLF files. Nothing becomes an option. An invalid regex shows rg's first error line, and no crash. Test: Task 1 `searchArgs` and `parseRgJson`.
3. **Replace safety.** If a file changes between preview and apply, it is not written. A pattern whose JS and Rust regex semantics differ on a match is refused per file. Applying never touches a path outside the root. Test: Task 1 `planReplace` and the service spec with a real temp dir.
4. **rg missing or slow.** With no `rg`, the tab says how to install it and falls back to `git grep` inside a repo. A huge repo streams without freezing (results render as they arrive), and typing cancels the stale run. Test: Task 1 `search()` with a fake host that has no `rg`, and the cancel test.
5. **Symbols on unsupported or odd files.** An unknown language, minified one-line JS, unbalanced braces, decorators, or a Python file with tabs. The outline degrades to "No outline for this file type." or a partial list, and never throws or hangs: the regex has no catastrophic backtracking and caps at 2,000 symbols. Test: Task 2 `outline` specs, including a 5 MB one-line input under 200 ms.

**Decided details:**
- `searchArgs`: `['rg', '--json', '--no-config', '--max-columns', '1000', '--max-filesize', '2M', ...flags, ...globs, '-e', text]`.
  - Flags: `-s` or `-i`, and `-F` unless `regex`. Add `-w` for whole word.
  - Globs: `-g <inc>` for each include and `-g !<exc>` for each exclude.
  - It searches the current directory (cwd = root). Paths are made root-relative with `projectRel`.
- `parseRgLine` handles rg's JSON events:
  - Only `match` produces a `Match`. Use `lines.text`, falling back to `lines.bytes` (base64, decoded by hand) shown as `[binary line]`.
  - The trailing `\n`/`\r\n` is stripped from `text`, and the `ranges` are converted from the `submatches` byte offsets with `byteToIndex`.
  - `summary` and `begin` give `null`. A non-JSON line gives `null`.
  - rg's `error` lines and a stderr-only failure become `{ error }`, using the first line.
- Missing `rg`: when the spawn fails (ENOENT or exit 127 with nothing on stdout), `search()` uses `git grep` inside a repo. Outside a repo it returns `error: RG_MISSING`.
  - The `git grep` argv: `['grep', '-n', '--column', '-z', '-I', '--no-color', '-i'|'', '-F'|'-E', '-w'?, '-e', text, '--', ...pathspecs from globs]`, run through `git()`.
  - With `git grep`, the column gives only the first range per line.
- Cancel: `search()` calls `stream.cancel()`. Matches that arrive after cancel are dropped. The host debounces with the 0.1 `latest()` guard.
- `sendText` gives `These are the <n> uses of <query>: <rel>:<line> (<trimmed text ≤80>), …`, capped by characters with `…and N more.`. A single match gives `<rel>:<line> (<text>)`.
- `planReplace`:
  - For literal mode, use the matches' ranges.
  - For regex mode, build `new RegExp('^(?:' + text + ')$', flags)` and require it to fully match each matched substring; if it does not, the file is skipped with `regex-differs`. Capture references `$1`..`$9`/`$&` are expanded via JS `String.prototype.replace` on that substring.
  - It works on the file text the service just read, rebuilding `after` from the line/range positions; CRLF is preserved.
- `applyReplace` checks each file before writing it:
  - It re-reads the file; if the text differs from `before`, the file is skipped as `changed`. A NUL byte or invalid UTF-8 in the head means `binary` or `not-utf8`.
  - The path must be inside the root, else `outside-root`.
  - Only then does it write.
- `rankFiles`:
  - Only files with a non-null `fuzzyScore(name, rel)` (from `core/shared/fuzzy.ts`) are kept.
  - They are ordered by tier (touched, then recent, then the rest), and within a tier by score descending, then by shorter path.
  - Basename matches score higher: add a bonus when the score against the basename alone is non-null.
  - An empty query returns touched, then recent, then the rest in path order, up to `limit`.
- Pane:
  - `preview` accepts `{ rel, line? }`. It pushes `files.preview` onto the **current** tab's stack, so `back` returns to Search or Symbols. From Files, 0.1 behavior is unchanged.
  - New views: `search.replace`, `quickopen` (a mode of the Search tab, toggled by `q`) and `symbols.results`.
  - `PaneState` gains `recent: string[]`, the last 50 previewed paths, most recent first.
- Keys, in priority order:
  - `search`: `up`, `down`, `enter preview`, `a add`, `s send all`, `c case`, `x regex`, `w word`, `i include`, `p replace`, `q quick open`, `esc`.
  - `search.replace`: `scroll` keys, `enter apply file`, `y apply all`, `a ask agent`, `esc`.
  - `quickopen`: `up`, `down`, `enter preview`, `a add`, `q search`, `esc`.
  - `symbols`: `up`, `down`, `enter preview`, `d definition`, `r references`, `c calls`, `a send`, `f find symbol`, `esc`.
  - `symbols.results`: `up`, `down`, `enter preview`, `a send`, `esc`.
- `docs/security.md` records the `--no-config` and `-e` rule, the replace guards, and the root confinement.

```ts
export type SymbolKind = 'function' | 'class' | 'method' | 'type' | 'interface' | 'enum' | 'const' | 'heading'
export type SymbolNode = { name: string; kind: SymbolKind; line: number; endLine: number; children: SymbolNode[] }
export function languageFor(rel: string): 'ts' | 'py' | 'go' | 'rs' | 'java' | 'cs' | 'md' | null
export function outline(rel: string, text: string): SymbolNode[] | null      // null = unsupported language
export function enclosing(nodes: readonly SymbolNode[], line: number): SymbolNode | null   // innermost
export const SYMBOL_CAP = 2000
// approx.ts
export type SymbolRef = { rel: string; line: number; text: string; container: string | null }
export function definitionArgs(name: string, lang: ReturnType<typeof languageFor>): SearchQuery   // regex over definition shapes for that language (or all)
export function isDefinitionLine(lang: NonNullable<ReturnType<typeof languageFor>>, name: string, line: string): boolean
export function referencesQuery(name: string): SearchQuery          // literal, whole word, case-sensitive
export function calleeNames(text: string, node: SymbolNode, lang: NonNullable<ReturnType<typeof languageFor>>): string[] // identifiers followed by "(" inside node's lines, minus keywords and the node's own name
// lsp.ts
export type LspOp = 'documentSymbol' | 'workspaceSymbol' | 'goToDefinition' | 'findReferences' | 'incomingCalls' | 'outgoingCalls'
export function parseLsp(op: LspOp, text: string, root: string): { symbols?: SymbolNode[]; refs?: SymbolRef[] } | null   // null = unrecognized format
// service.ts
export type Source = 'lsp' | 'approximate'
export async function fileOutline(host: Host, root: string, rel: string): Promise<SymbolNode[] | null>
export async function findSymbol(host: Host, root: string, name: string): Promise<SymbolRef[]>     // definition-shaped lines across the project
export async function definitions(host: Host, root: string, name: string, fromRel: string): Promise<SymbolRef[]>
export async function references(host: Host, root: string, name: string): Promise<SymbolRef[]>  // container filled via outline of each file (cached per call)
export async function incoming(host: Host, root: string, name: string): Promise<SymbolRef[]>    // references grouped by enclosing function/method
export async function outgoing(host: Host, root: string, rel: string, node: SymbolNode): Promise<SymbolRef[]> // calleeNames → first definition each
export function symbolSendText(name: string, def: SymbolRef | null, refs: readonly SymbolRef[]): string
```

**Decided details:**
- **Outline regexes.** They are line-anchored and have no nested quantifiers over the same characters; that rule is reviewed explicitly.
  - TS/JS: `function`, `class`, methods inside classes, `interface`, `type`, `enum`, and `export const X =` (arrow functions count as `function`).
  - Python: `def` and `class`, nested by indentation (a tab counts as 8 columns).
  - Go: `func`, including receivers (`func (r *T) Name`, which becomes a method under type `T` when `T` is declared in the file), and `type`.
  - Rust: `fn`, `struct`, `enum`, `trait`, and `impl` blocks as parents.
  - Java and C#: classes, interfaces, enums and methods.
  - Markdown: `#`–`######` headings, nested by level.
- **Nesting.** C-like languages nest by brace depth, counting `{}` outside strings and `//`/`/* */` comments with a small scanner. `endLine` is the line where the depth returns. Unbalanced input closes everything at EOF.
- **Limits.** Stop at `SYMBOL_CAP` symbols. Lines over 2,000 characters are scanned only for their first 2,000 characters.
- **Approximate definitions and references.** `references` is `referencesQuery` (literal, whole word, case-sensitive). `definitions` keeps the `findSymbol` hits whose `isDefinitionLine` is true, ordering same-file hits first. When the language is unknown, use all languages' shapes.
- **LSP output.** The LSP tool returns formatted text, and its exact format must come from a real capture:
  - First choice: run the LSP tool in this session against a fictional TS fixture, if it is available.
  - Second choice: the bundled plugin-authoring `reference.md` / `examples/`.
  - Commit the captured text as fixtures. Each parser accepts small variations (order, extra blank lines, `file:line:col` and `file (line N)` forms) and returns `null` on anything it does not recognize; the host then falls back to approximate.
- **Text to the agent.** `symbolSendText` gives `<name> (<rel>:<line>) and its <n> references: <rel>:<line>, …`, with the same 12,000-character cap as Task 1.

**Decided details:**
- **Search layout, top to bottom:**
  - The query Input, with placeholder `Search` (or `Go to file` in Quick Open).
  - A toggles row `Aa .* \b` (the active ones in the accent color with a text marker, so color is never the only signal), plus the include/exclude summary when it is set.
  - The results: a file header row `<rel> (<n>)`, then match rows `  <line>: <text>` with the match drawn in the accent color.
  - A summary row: `<total> results in <files> files · <ms> ms`, `Results truncated.`, `No results.`, or the error / `RG_MISSING` text (dim). When the `git grep` fallback runs, it shows ` · git grep`.
- **Query behavior.** Typing restarts the search after 150 ms through `latest()` and cancels the previous stream. Results render as they arrive, re-rendering at most every 100 ms.
- **Toggles and filters.** `c`/`x`/`w` toggle case, regex and whole word. `i` focuses a second Input `Include/exclude: src/** !**/*.test.ts` (parsed with `parseGlobs`).
- **`enter` on a match** previews at its line. The 0.1 preview scrolls to that line and marks it.
- **`a` and `s`** hand `sendText` to the agent (one match, or all) through the existing hand-off.
- **`p` replace:**
  - It shows a replacement Input. `enter` opens `search.replace`, which lists each `ReplaceFile` as a collapsible diff (rendered with the 0.1 diff renderer from `previewText`) plus a `Not replaced` section with the reasons.
  - Applying asks for confirmation: `enter` asks `Replace <count> matches in <rel>?` for the current file, and `y` asks `Replace <count> matches in <files> files?` for all.
  - `a` hands `Replace "<text>" with "<replacement>" in: <rel>:<line>, …` to the agent.
  - After applying, toast `Replaced <n> matches in <f> files.` and refresh both the search and Files.
- **`q` toggles Quick Open:**
  - The same Input is matched against `quickOpenFiles` (cached; refreshed on file events) with `rankFiles(touched = ActivityLog paths, recent = PaneState.recent)`.
  - Rows show the basename, then the dim folder through `fitPath`. Touched files show the 0.1 activity marker.
  - `user.ts:42` previews at line 42.
- **Symbols layout:**
  - The header `Outline: <rel> · <source>` shows the Files selection, else the last file the agent touched, else `Select a file in Files.`. Below it is the nested outline (indent 2 per level, plus a kind glyph or a letter in ASCII).
  - `f` focuses an Input `Find symbol`; the results go to `symbols.results`.
  - `d`/`r`/`c` act on the selected symbol:
    - `d` previews the definition directly when there is one, and lists the candidates when there are several.
    - `r` lists references grouped by file, with their container.
    - `c` shows an expandable tree with `Callers` and `Calls` sections; `enter` expands a node lazily.
  - `a` hands `symbolSendText` to the agent.
- **LSP gating:**
  - On first entry to Symbols, call `$.tool.check({ tool: 'LSP', … })` for a `documentSymbol` request. `allow` means use LSP for every operation.
  - `ask` adds one row: `Exact symbols need permission to use the LSP tool.` with a `[ Use LSP ]` Button that makes the first call on purpose, and approximate data stays meanwhile.
  - `deny`, a tool error, or `parseLsp → null` means approximate, and the header says so.
