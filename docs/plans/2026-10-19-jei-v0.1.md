# JEI v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship JEI 0.1 on Claude Code and OpenCode: the pane shell with four tabs, the Files tab, and the Git tab's repository row, Changes and diff view, from one open-source repository.

**Architecture:** A host-independent `core/` (pure TypeScript: parsers, argv builders, view models, key map) consumed by two thin adapters: `hosts/claude-code/` (a Claude Code mod drawn with `$.ui`) and `hosts/opencode/` (an OpenCode 2.x plugin: a server entry that runs git and files, and a TUI entry drawn with Solid + OpenTUI, linked by RPC). The repo root is both the Claude Code plugin and the `opencode-jei` npm package.

**Tech Stack:** TypeScript/TSX, zero runtime dependencies, Bun (dev toolchain and tests for `core/` and OpenCode), `claude plugin validate` / `claude plugin test` (Claude Code adapter), `@opencode/plugin` 2.0.32 + `@opentui/solid` 0.5.17 (dev/peer only), GitHub Actions, release-please, npm trusted publishing.

**Spec:** `PRD.md` (repo root). Read §4, §5, §6.1, §6.4, §7, §8 and §9 before any task.

## Global Constraints

- All UI text, docs, comments and commit messages in English.
- No secrets, tokens, personal paths, usernames, emails or real project names in any file, fixture, screenshot or commit. Fixtures use the sample repo `acme-app` and fictional authors (`Ana Rivera <ana@example.com>`, `Leo Park <leo@example.com>`).
- `core/` imports nothing from `claude-code`, `@opencode/*`, `solid-js`, `@opentui/*`, `node:*` or `bun:*`; it uses only ECMAScript built-ins.
- Zero runtime dependencies. `@opencode/plugin`, `@opentui/core`, `@opentui/solid`, `solid-js` are `peerDependencies` (optional) + `devDependencies`. `typescript` and `@types/bun` are dev only.
- Every relative import names its file with its extension (`./status.ts`, `./pane.tsx`).
- Never a shell string (`sh -c`, `cmd /c`): every process is an argv array.
- Every git command: `['git', '--no-optional-locks', '-C', root, ...]` with env `GIT_OPTIONAL_LOCKS=0`.
- Every view renders at 40 columns without breaking.
- Keys are one lowercase letter or digit (plus `enter`, `esc`, arrows), identical on both hosts, all defined in `core/keys.ts`.
- Destructive actions (discard, discard all, amend over a pushed commit is out of scope) always confirm.
- Minimum Claude Code 2.1.302. Minimum OpenCode 2.0.32 (2.x line only).
- Test file naming: `*.spec.ts(x)` run by `bun test` (`core/`, `hosts/opencode/`); `*.test.ts(x)` run by `claude plugin test` (`hosts/claude-code/` only). Never mix: `claude plugin test` loads every `*.test.ts` in the plugin folder.
- Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`, `ci:`); release-please reads them.
- License MIT, copyright line `Copyright (c) 2026 The JEI contributors`.

## Review Focus

1. **Paths with spaces, unicode and Windows separators** (`C:\Users\x\my app\ñ.ts`, `src/a b.ts`): tree, status, diff and open must keep them intact. Tests: Task 3 (`paths`), Task 4 (`-z` parsing keeps spaces/newlines), Task 9 (open argv).
2. **Not a git repo / empty repo / detached HEAD / no upstream**: Git tab shows a plain state, never a crash. Tests: Task 4 (`parseStatus` headers for `(detached)`, `(initial)`, no upstream), Task 15 and Task 19 (not-a-repo view).
3. **Agent changes files while the pane is open** (status refresh racing a commit): stale results never overwrite newer ones. Test: Task 8 (`latest()` generation guard).
4. **Secrets in the change set** (`.env`, `id_rsa`, `*.pem`) during smart commit: JEI stops and shows them first. Test: Task 6 (`sensitivePaths`).
5. **Huge or binary files and huge diffs** (a 50 MB log, a PNG, a 20k-line diff): preview shows a notice, diff is capped, nothing hangs. Tests: Task 7 (preview classify), Task 5 (`capDiff`).
