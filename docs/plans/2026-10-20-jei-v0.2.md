# JEI v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship JEI 0.2 on Claude Code and OpenCode: the Git tab's Graph (lanes, expand a commit, commit actions, ✦ for the agent's commits, filter, fetch) and Branches (switch, create, compare with main).

**Architecture:** As in 0.1. All parsing, layout, argv and decisions live in `core/git/` as pure functions plus thin `Host`-based service calls. Each host adds a Graph section to its Git view and a `git.branches` view. Commit and compare diffs reuse the 0.1 diff view through a generalized diff target. Hook-firing actions (switch, checkout, revert) on Claude Code go through the existing `runHookAware`.

**Tech Stack:** Unchanged from 0.1 (TypeScript, Bun, `claude plugin test`, `@opencode/plugin` 2.0.32, `@opentui/solid` 0.5.17, zero runtime dependencies).

**Spec:** `PRD.md` §6.4 (Graph, Branches, Keys, Build), §7 (`graphLimit`, `glyphs`), §9 (privacy), §11 (0.2 row). Docs: `docs/architecture.md`, `docs/design.md`, `docs/hosts.md`, `docs/conventions.md`, ADRs 0009 and 0010.

## Global Constraints

- Everything from the 0.1 plan's Global Constraints still applies (`docs/plans/2026-10-19-jei-v0.1.md`). The most relevant: English only; no personal data (fixtures use `acme-app`, Ana Rivera / Leo Park `@example.com`); `core/` stays pure; argv only; every git call goes through `core/git/run.ts` `git()` with `GIT_ENV`; keys are defined only in `core/keys.ts`; destructive actions confirm; a feature lands on both hosts or neither.
- Every view renders at 24, 40, 80 and 120 columns and on short panes (≤10 rows) without overflowing, and survives a live resize. Truncate with `core/shared/fit.ts`.
- Graph glyphs come in three sets that follow `glyphs`. `nerd`/`plain` use `● │ ─ ╮ ╯ ╭ ╰ ├ ┤`; ASCII uses `* | - \ /`. Every glyph is one cell wide.
- `graphLimit` (default 200) is the page size. "Load more" appends one more page.
- JEI never stashes, never force-pushes, never creates a merge commit the user did not choose, and never runs `reset`.
- Plan-level simplifications, to be logged in PRD §13 in Task 4:
  - The toolbar is **fetch** (`t`) and **filter** (`f`). Pull and push stay inside Sync (`e`, from 0.1). Refresh is automatic.
  - Reverting a merge commit is refused with `Reverting a merge commit is not supported.`

## Review Focus

1. **Branch names and refs from untrusted repos.** A name like `-x`, `--upload-pack=…`, `a..b`, or a space or unicode in a branch or tag must never become a git option or a wrong ref. Every user-supplied name is checked with `git check-ref-format --branch`. Refs passed to commands that take revisions go after the options, and `--end-of-options` is used where git supports it. Test: Task 2 `branch-actions`.
2. **Remote URLs with credentials** (`https://user:token@github.com/o/r.git`). "Open on GitHub" never puts the userinfo in the URL it opens, and the toast never shows it. Test: Task 2 `commitWebUrl`.
3. **Histories that are huge, wide or odd.** A root commit, an octopus merge (3+ parents), many parallel lanes on a 24-column pane, and a parent that lies outside the loaded page. Layout never throws, never exceeds the width (overflowing lanes collapse to `…`), and "Load more" keeps the lanes stable. Test: Task 1 `layoutGraph`.
4. **Switching with uncommitted changes, or a detached HEAD.** JEI asks first. Git's own refusal (local changes would be overwritten) surfaces as a toast with its first line, and the work tree is untouched. Test: Task 2 `switchPlan` plus the service spec with a real repo.
5. **Agent-commit marking when HEAD moves for other reasons.** The user commits from JEI, switches branch, or the agent runs `git checkout`/`reset`. Only commits that become newly reachable during an agent tool call get ✦. A branch switch by the agent marks nothing. Test: Task 1 `AgentCommits`.

**Decided details:**
- `logArgs`:
  - Shape: `['log', '--topo-order', '--no-color', '-z', '--format=%H%x00%P%x00%an%x00%at%x00%D%x00%s', '-n', String(count + 1), ...]`.
  - The `+1` tells `graph()` whether there is more.
  - `branch === 'all'` adds `--all`. A named branch adds `--end-of-options <branch>` and nothing else.
  - `message` adds `--fixed-strings -i --grep=<text>`. `author` adds `--fixed-strings -i --author=<text>`.
  - `path` adds `-- <path>` last.
- `parseGraphFilter`:
  - Takes space-separated `author:…`, `path:…` and `branch:…` tokens, plus `branch:*` meaning `'all'`. The rest of the text joined is `message`.
  - Quotes allow spaces (`path:"src/a b.ts"`). Empty text gives `{}`.
- `parseLog` reads `%D` into badges: `HEAD -> main` gives `head` + `local main`; `origin/x` gives `remote`; `tag: v1` gives `tag`. Skip the `origin/HEAD` entry.
- `layoutGraph`, standard lane assignment:
  - Each lane holds the hash it is waiting for.
  - A commit takes the leftmost lane that waits for it, or a new lane.
  - Its first parent inherits that lane, and other parents take free or new lanes.
  - Lanes waiting for the same hash merge in the connector row.
  - `glyph` is the commit row: `●` (ASCII `*`) at `column`, `│` (`|`) on other live lanes, cells separated by one space.
  - `connector` is the row drawn below the commit when lanes fork, merge or end (`├─╮`, `│ ╰─╮`, `╭─╯`, ASCII `|\`, `|/`). It is `null` when nothing changes.
  - A parent outside the loaded commits keeps its lane open to the end; it does not throw.
- `fitGraph` keeps the commit's own cell. When the lanes exceed `maxCells` it replaces the lanes beyond the budget with one `ellipsis` cell.
- `commitFilesArgs`:
  - Shape: `['diff-tree', '-r', '-z', '--root', '-M', '--no-commit-id', '--name-status', <hash>]` and the same with `--numstat`.
  - Merge commits compare against the first parent. Verify the `diff-tree` flags for that against real git and keep the first form that works.
  - The root commit lists every file as `A`.
- `commitDiffArgs` gives `['diff', '--no-color', '--no-ext-diff', '-M', `${hash}^`, hash, '--', path]`. For the root commit it gives `['show', '--no-color', '--format=', hash, '--', path]`.
- `AgentCommits` tracks which commits the agent made:
  - The host calls `toolStart(HEAD, nowSeconds)` before an agent tool runs. On Claude Code that is the agent's shell and write tools. On OpenCode it is any tool, if the API has a before-hook; otherwise use `lastHead()` and the tool's start time.
  - After the tool, the host calls `toolEnd(await newlyReachable(host, root, lastHead(), HEAD))`. On every other refresh, including JEI's own actions, it calls `observe(HEAD)`.
  - Marking rule: `toolEnd` marks each candidate whose committer time is ≥ the tool's start time minus 2 s of clock slack, then sets `lastHead` to HEAD. A branch switch only reaches older commits, so it marks nothing. A JEI commit goes through `observe`, so it is never marked.
  - Cap at 1,000 hashes, dropping the oldest. `toJSON`/`from` persist the set in session state.
- Pane state: `'open-diff'` with `source.kind !== 'working'` pushes `git.diff` from whichever Git view is on top (`git` or `git.branches`), so `back` returns there. A new action `{ type: 'branches' }` pushes `git.branches`.
- Keys:
  - `git` adds, in priority order after `c commit`: `y copy hash`, `a ask`, `b branches`, `f filter`, `t fetch`. Keep `g generate` and `e sync` in the list after them.
  - `git.branches` is `up, down, enter switch, n new, c compare, f filter, esc back`.
  - `git.diff` keys are unchanged.

**Decided details:**
- `branchesArgs` is `['for-each-ref', '--format=%(refname)%00%(objectname)%00%(upstream:short)%00%(upstream:track,nobracket)%00%(HEAD)', 'refs/heads', 'refs/remotes']`. `track` values: `ahead 2, behind 1`, `gone`, or empty. `gone` gives `upstream: null`.
- `switchPlan`:
  - A local target gives `['switch', <name>]`.
  - A remote target `origin/x` gives `['switch', <x>]` when a local `x` exists, else `['switch', '--track', <origin/x>]`.
  - `dirty` sets `confirm` to `You have uncommitted changes. Switch and carry them over?`. The steps never contain `--force`, `--discard-changes` or `stash`.
  - Names come from `for-each-ref`, so they are valid refs. Still, a name starting with `-` is refused: the plan returns no steps and `confirm: null`, and the service throws `GitError`.
- `createPlan` gives `['switch', '-c', name]`, plus `start` when given (a full hash from the graph). `start` is passed only after checking it matches `/^[0-9a-f]{40}$/`.
- `fetchAll` is `['fetch', '--prune']`. It reports failure through `GitError` like Sync.
- `commitWebUrl`:
  - Supports `github.com` and `gitlab.com` remotes in `git@host:o/r(.git)`, `ssh://git@host/o/r(.git)` and `https://[userinfo@]host/o/r(.git)` forms.
  - Gives `https://github.com/o/r/commit/<hash>` or `https://gitlab.com/o/r/-/commit/<hash>`, never with userinfo. Everything else gives `null`.
- Revert of a commit where `isMerge` (Task 1) is true: the host shows `REVERT_MERGE_REFUSAL` and runs nothing.
- Checkout of a commit is detached and confirmed by the host with `Check out <short> (detached HEAD)?`. Revert is confirmed with `Revert <short> "<subject>"?`.
- `docs/security.md`: the credential-free web URL, `--end-of-options` and `check-ref-format`, and "never stash or force".

**Decided details:**
- **Graph section.** It is a collapsible section header `▾ Graph` (`▸` when collapsed) below the Staged and Changes groups, sharing the Git list's scroll and focus.
  - Each commit row reads: graph glyph (`fitGraph` with a budget of `min(lanes, max(3, floor(inner/4)))` cells), ✦ if `agent.has`, short hash (7), subject, and author plus relative time when width ≥ 60.
  - Ref badges go after the hash in the accent color with a text label (`main`, `origin/main`, `v1.0`, `HEAD`), dropped first when the row is narrow.
  - The connector row shows only the glyph.
  - The last row is `Load more` when `more` is true.
  - Below 24 columns, show the hash and subject only.
- **Enter on a commit** toggles it expanded inline. It lists `CommitFile` rows (status letter, path through `fitPath`, `+a −r`), and enter on a file opens the diff with source `commit`. `j`/`k` in the diff walk that commit's files.
- **Commit-row actions**, as hint Buttons while a commit row is focused:
  - `y` copies the full hash with the host clipboard call from `claude-code.d.ts`. If it reports not copied, toast `Copy failed: <reason>.`
  - `a` hands `Explain commit <short> ("<subject>").` to the agent through the existing hand-off path.
  - In the expanded commit there are Buttons for `Checkout` (confirm) and `Revert` (confirm, refused for merges), and `Open on GitHub` or `Open on GitLab` only when `webUrl` returns a URL.
  - Checkout and revert run through `runHookAware` when `snapshot.hooks` is true.
- **`f` focuses a filter Input** above the graph (placeholder `Filter: text, author:, path:, branch:*`). Enter applies it, and an empty filter clears. When a filter is active, the section header shows `Graph (filtered)`.
- **`t` runs `fetchAll`.** The repository row shows `fetching…` while it runs; a failure shows a toast with the first error line.
- **`b` opens `git.branches`.**
  - The list shows local branches, then a `Remote` header with the remote branches. Each row has the current marker `*`, the name (`fitPath`), `↑a ↓b`, and upstream `gone`.
  - Enter switches (confirm when dirty, through `runHookAware` when hooks are on).
  - `n` opens an Input `New branch name`. On a commit row in the graph, the new branch starts from that commit, and the prompt says `from <short>`. The name is checked with `validBranchName`; an invalid name shows a toast `Not a valid branch name.`
  - `c` lists `compare(base, selected)` files under a header `Compared with <base>`. Enter on one opens a diff with source `compare`. When there is no base, toast `No main branch to compare with.`
- **✦.** `activity.ts` calls `toolStart`/`toolEnd` around the agent's tool calls (PreToolUse and PostToolUse for the shell tools, the same hook entry 0.1 uses) and `observe` on other refreshes. The set lives in `state.ts` via `toJSON`.
