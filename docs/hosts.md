# Hosts

> Purpose: verified API facts, limits and version floors for Claude Code mods and OpenCode 2.x plugins · Status: current · Last reviewed: 2026-10-20

Source: `PRD.md` §4.2 to §4.4, verified in October 2026. Both APIs are young; a host's exported types are the contract. If a fact here turns out wrong, fix this file and say so in the commit.

## Claude Code

Minimum version **2.1.302**. CI also runs against the latest release. The mod API is early access.

**Mod rules.** A hooks module has no Node, no DOM, no `WebAssembly`, no `eval` and no dynamic `import()`. Imports must stay inside the plugin folder (which is why the whole repo root is the plugin and `core/` ships with it). Relative imports keep their `.ts` extension. `userConfig` values in `plugin.json` are strings; on/off settings are `"on"`/`"off"` pickers.

**Types.** `.claude-plugin/types/` is laid by Claude Code, gitignored and never committed. The plugin's own state contract is `types/index.d.ts`.

Retained v0.1 working-diff state is normalized by shared core `normalizePane` at Claude state reads/updates and OpenCode panel/command memory loads. It preserves selections and flags across reload; drawing performs no migration writes. See `docs/decisions/0012-git-history-evidence-and-state.md`.

**Keys.** Native pane hotkeys come through `Button`s: one digit or one lowercase letter. Tab walks the focus ring; arrows raise `ui.scroll` while the rendered tree exceeds the viewport, otherwise they can walk that ring too. Esc returns to the prompt. Virtualized views report hidden content through `FilesView.scrollable`; the shared shell appends one empty row beyond its fixed visible frame to retain native scroll routing. The scroll hook consumes events even when a view intentionally ignores them. `Client` has its own raw keys but cannot wrap native hook closures; JEI retains native elements and the single-key rule from `core/keys.ts` (ADR 0024).

**Layout and surfaces.** Docking beside the transcript needs `/tui fullscreen`; a pane opened unasked seats from about 110 to 144 columns, inline below that. Body width is `e.props.bodyColumns` (expect 40 to 60). The terminal is first class; the Desktop app also draws mod panes (`e.surface === 'desktop'`), so every tree must be valid there and work by click. Mods do not load in the Desktop app's WSL sessions, the VS Code chat panel or `claude -p`. Mouse works only in the fullscreen layout.

**Adapter structure.** Status: current for the pane shell, Files, Git, Search, Quick Open and Symbols.

**Search and Symbols (0.3).** `search.tsx` and `symbols.tsx` return the existing header/body/action shape. Root-keyed session atoms retain queries, results, reviewed replacement plans and source labels across preview Back. Search debounces 150 ms, cancels its prior stream, publishes batches at most every 100 ms and guards late replies by session/root/generation. Quick Open caches the shared file list and invalidates it through `onRefresh`. Register routes native focus/scroll and stops work on tab/preview/cwd changes, pane close and session end. Hand-off checks `prompt.fill().isFilled` and never starts a model request. Replacement uses shared plan/apply services, confirms reviewed files, lists skip reasons and reports partial counts before Files/Search refresh.

Symbols cancellation also clears that root's transient busy/editor/pending permission state under its generation guard; an older completion cannot clear newer work. Subject selection is retained separately from command/permission focus. Send resolves the selected workspace definition or call child and freshly gathers its own references; reference lists retain their queried subject. Pending call permission includes the hierarchy node id, so deliberate LSP consent upgrades that node's bounded children/source label in place. Scroll selection and native Button focus keys are identical for Use LSP and Apply file.

Search and Quick Open keep independent text and retain their last selected data subject when focus moves to a command. Submitting a Quick Open value ranks that submitted text. Rejected file-list promises are evicted, pane close invalidates caches, and native enumeration overflow shows `File list too large for this host (4 MiB). Narrow the project and retry.`; streaming enumeration is deferred. Session start clears persisted Search/Symbols busy/editor/confirmation/loading/permission flags. Focus events and boundary scrolls that change no selection avoid state writes.

Approximate outlines publish before the optional LSP attempt with a loading notice; command/session/cwd hooks launch that work without awaiting LSP, and cwd re-enters Symbols. Deliberate LSP requests retain the requested title, preview a unique definition, report refusal/failure and label mixed Calls sources accurately. JEI's own non-shell LSP calls are excluded from agent activity using the host's unforgeable `next.origin`; shell Git refresh remains unchanged. Close/session-end observers forward the original event on bookkeeping failure, and unresolved preview roots render a safe notice.

Every Symbols preview entry cancels pending Symbols work, including outline/reference rows, unresolved call children and completed definitions. Request guards require the current Symbols view, so a preview retaining the Symbols tab cannot admit a late LSP call or result. Selected-file validation and LSP position reads reuse `core/symbols/service.ts::readSource` after `projectHost` resolution.

Installed declarations verify `tool.check({tool:'LSP',input:{operation,filePath,line,character,query?}})` is side-effect-free; `tool.call({tool:'LSP',...input})` runs the normal permission flow. Each concrete request is freshly checked, including lazy child calls. Only allow runs automatically. Ask keeps approximate data and exposes deliberate Use LSP; denial, errors and unknown text fall back. One-based identifier positions are verified against confined UTF-8 source. Document/workspace operations still carry a real file. Parser calls receive the resolved Host platform. Fixtures remain synthetic; no positive live LSP output format has been verified.

`files.tsx::projectHost` resolves new-flow double-slash roots through canonical `fs.stat(...,{resolve:true}).realPath`, recognizing only rooted drive/native UNC or single-leading-slash POSIX evidence. Missing/relative/still-ambiguous evidence refuses new Search/Symbols/preview access; a backslash inside a POSIX component is insufficient. Existing tree/Git inference is unchanged. Code has no highlight-line prop: line targets use bounded source rows and a native gutter marker. CSV/TSV retain optional raw text, already allowed by the preview RPC schema. ADR 0021 records compact controls, editor focus and evidence limits. Actual silent pending-pull cancellation remains live-host QA.

The v0.3 Host additions are built on both adapters. Claude `stream` uses the verified object-form `$.process.spawn({ argv, cwd?, env?, input? })`, pulls `{ stream, text }` chunks, and returns newline-framed stdout plus collected stderr and the generator's `{ code, signal }` exit. Closing the source requests cancellation; optional signal/timeout are handled outside the spawn request, with `$.clock.after` for timeouts. A bounded consumer queue preserves backpressure. `writeText` delegates to `$.fs.write(path, text)`, whose 4 MiB limit also bounds shared replacement reads. OpenCode uses argv-only `spawn` with `shell: false`, `windowsHide`, UTF-8-decoded streams and native signal/timeout, and `writeFile(path, text, 'utf8')`. No runtime dependency was added. Neither adapter promises an atomic filesystem compare-and-swap.

Installed Claude declarations expose `AbortController`/`AbortSignal`, object-form spawn and `HookStream.result`. The Symbols adapter captures a host-local signal around fallback stream/run calls: cancellation closes active streams and prevents later sequential callee searches from starting. It does not interrupt an already-running `$.process.run` or LSP tool call; generation guards reject their stale completion. A cancellation check after each pending stream pull prevents late chunks from parking a canceled producer behind backpressure. The independent source-result rejection is consumed as well as the iterator result. Silent pending-child cancellation still needs live-host QA.

Each adapter rejects/cancels an stdout line or collected stderr above an 8 MiB decoded-text character budget, independently of the fallback service's joined-output cap. Claude's queue backpressures at 64 lines or 1 MiB. Large JSON-escaped lines can therefore return an explicit stream error even below rg's raw file-size limit.
- `hooks/register.tsx` is wiring only: `session.start` registers `/jei`, writes `cwd` and the opening tab, and arms the auto-open only on a fresh session (the pane state was never written), so a hot reload never reopens a pane the person closed; a pass-through `ui.render` hook on `PromptHint` opens the pane unasked once, only when armed, `options.startOpen` and `e.viewport.isFullscreen` is true (session start knows no viewport); `command.run` for `jei` answers its own command (`JEI opened.`, `JEI closed.`, `JEI opened on <Tab>.`) and opens with `focus`. Bare `/jei` closes only a pane that is placed and shown, otherwise brings it forward. An open that is not placed answers `JEI is open but not shown yet: <reason>.`, a rejected open or close answers `JEI could not open: …` / `JEI could not close: …`. `/jei <path>` resolves the path against `cwd` (`projectRel`): absolute or relative, outside the project or escaping with `..` answers `That path is outside the project.` and changes nothing; `classic.CwdChanged` updates `cwd` (its `.catch` passes the event on); `ui.render` on `{ component: 'Pane', requestId: 'jei' }` calls `renderPane`.
- `hosts/claude-code/state.ts` declares the atoms (`pane`, `cwd`, `activity`, `git`, `gitUi`, `preview`, `tree`, `tick`, `history`, `searches`, `symbols`, plugin `jei`) and the accessors other files use (`readPane`, `updatePane`, `setCwd`, ...). `claude plugin validate` traces a state call only to an atom declared in the same file, and follows `$` across an import only into a function declaration, so state calls live in `state.ts` and accessors are `function` declarations. A matcher's `requestId` must be a literal.
- `types/index.d.ts` is self-contained (no imports) and repeats core's shapes as JSON; `state.ts` fails to compile if they drift. `GitSnapshot`'s count `Map`s are stored as records (`gitState`), because state is JSON.
- `hosts/claude-code/host.ts` is `claudeHost($, platform)`: `$.process.run` (no signal support: an aborted call never starts; a truncated stdout throws `Output too large: <argv>` rather than handing core a partial list), `$.fs.list`, `$.fs.stat(path, { resolve: true })` (no `realPath` gives `null`: fail closed), `$.fs.read` (bytes mode for `readHead`), `$.model.complete` (model `haiku` when empty, 30 s timeout; no answer throws).
- `hosts/claude-code/pane.tsx` draws the shell from `bodyColumns` and `scroll.bodyRows` on every render. Tabs are `Button`s keyed `tab-1`..`tab-4` with hotkeys `1`..`4`, the current one `variant="primary"` and bold (non-plain, so `primary` shows and the hotkey mark is not doubled). The terminal draws each as `[ 1 Files ]`, so the adapter calls core's `tabBar` with 4 cells of chrome per tab; on this host the 2-space gap therefore often drops to 1 (at 24 columns: `[ 1 ] [ 2 ] [ 3 ] [ 4 ]`). A `Text` takes no `key`, so named rows (`rule`, `header`, `hint`, `body-<n>`) are keyed `Box`es holding one `Text`.
- `hosts/claude-code/files.tsx` (plan Task 11) draws the Files tab for `pane.tsx`: header (root name, or the filter `Input` after `f`), a body window anchored to the selected row's id (1 row of context from 5 body rows, kept across resizes), and the letter actions. Rows are a keyed gutter `Box` (`glow-<rel>` while glowing, `mark-<rel>` once touched, else `gut-<rel>`) and a plain `Button` keyed `row-<rel>` holding the name `Text` and a right-aligned status `Text`. Enter on a folder toggles it, on a file opens the preview (`Code`, `Markdown` with `m` for source, a `fitTable` text table for CSV/TSV, `Image` for PNG on the terminal, else a notice). The preview draws the file named by the `preview` atom (`rel`), so follow-agent never changes it. Its path header is a plain `Button` keyed `preview-title`; the shell supplies the visible `q` Back control; Esc never reaches a pane (ADR 0009). The hint line stays down to 3 rows on Files (bare below 10), because the letter keys are its Buttons' hotkeys. `a` calls `$.prompt.fill({ text: mentionText([rel]), mode: 'insert' })`; `o` runs `openFile` (the native path; a runnable type with no `editorCommand` is refused with the toast `Set editorCommand to open this file type.`) and toasts `Can't open <name>: <first line>.` on failure. Mobile draws no `Input` and no `Select`, so the adapter checks `e.surface` as well as the element table: the filter and the commit message show as text and Commit names the mode. Listings (`listDir`), the filter's file list (`allFiles`) and the current preview (only one is kept; opening a preview clears it) are module caches read while drawing (a draw may read but never write state). `forgetPaths` drops the root's and every ancestor's listing, the path's own listing and those below it; `forgetAll` drops every listing of the root. A failed listing draws `Can't read this folder.` and is dropped on the next toggle or refresh, never retried per frame; a failed preview draws `Can't read this file: <first line>.` when a caught exception has a message, otherwise `Can't read this file.` for the core's null-only read error The adapter remembers the element `ui.focus` last landed on; the selected row is inverted unless the pane holds the keyboard and the ring is on that row. `ui.focus` on a `row-` element selects it; `ui.scroll` moves the selection (tree) or the first line (preview) and answers `{}` because the pane draws its own window.
- `hosts/claude-code/activity.ts` (`registerActivity`): `tool.call` captures shell attribution evidence, invokes `next(e)` exactly once and finalizes attribution in `finally`; attribution failures are contained. After a result, activity/follow bookkeeping remains unawaited: it classifies (`classifyTool`; Grep and Glob add their result's `filenames`), maps paths with `projectRel`, touches the `activity` atom when allowed, and optionally reveals/selects the first path. Writes and git actions schedule a refresh after 300 ms of quiet, at most 1.5 s into a burst. Unclassified shell calls refresh everything. Refresh drops caches, reads Git through a per-session latest-wins guard, refreshes an open file filter and bumps `tick`. The log keeps 500 touches; a 250 ms clock redraws while a row glows. `classic.SessionStart` watches HEAD/index; `classic.FileChanged` schedules the same refresh, and cwd changes start it without awaiting it. The validator follows `$` through top-level function declarations; activity timers retain their existing module lifetime.
- `hosts/claude-code/git.tsx` (plan Task 12) draws the Git tab for `pane.tsx`. Header: the repository row (`acme-app  ⎇ main*  ↓2 ↑1  hooks  Sync`): the repo name from 100 columns, `Sync` (a plain `Button` keyed `sync`) from 60; past that the hook marker, then a busy label, drop, the branch shortens to 10 cells, then `↓↑` drops. A detached HEAD reads `⎇ (detached a41f9c2)` and no upstream `no upstream`, both `warning`. Not a repository: `This folder is not a git repository.` and an `Initialize repository` Button (`init`). Body: an open question pinned on top (a muted rule, one line, its Buttons), then the message `Input` (`message`; placeholder `Message (enter to commit on "main")` from 60 columns when it fits, else `Message`; Enter commits), a row of Commit (`commit`, primary, always labelled `Commit` so the row says it once; with an empty message a dim `[ Commit ]` keyed `commit-off` that cannot be pressed; on mobile it is labelled with the mode's full name), the mode Button (`commit-mode`: click/Enter cycles Only, & Push, Amend without committing; unlike a focused Select it releases arrows for list navigation, ADR 0024) and `✦ Generate` (`generate`), wrapped onto more rows when narrow, then Graph, Staged and Changes. A group header is a plain `Button` (`group-staged`, `group-changes`) that collapses it, with `Unstage all` / `Stage all` / `Discard all` (`unstage-all`, `stage-all`, `discard-all`) when they fit and its count at the right. A file row is a plain `Button` (`staged-<path>`, `change-<path>`): status letter, basename, the folder from 60 columns, `+12 −3` right-aligned in a column as wide as the widest visible count from 32. Enter opens the diff. Keys (hint Buttons): `s` stages the selected change (or the whole group on its header), `u` unstages, `d` asks to discard, `c` commits, `g` generates, `e` syncs. Discard (one or all) always asks first: `Discard` / `Cancel` (`confirm-discard`, `confirm-cancel`), and nothing runs until `Discard`. A commit reads a fresh snapshot first. While a file is unmerged, Commit toasts `Resolve conflicts first.` and runs nothing. Files that look sensitive ask `These files look sensitive: .env` (the whole list, wrapped over rows; on a short pane cut to `+N more` so the Buttons stay) with `Commit anyway` / `Cancel`; `Commit anyway` covers only the paths it showed, and a new one asks again; a diverged Sync asks with `Merge` / `Rebase` / `Ask Claude` / `Cancel` (Ask Claude fills the prompt). An operation shows its label (`Committing…`, `Syncing…`, `Generating…`) in the repository row and refuses a second one meanwhile (the check and the set are one state update; `session.start` clears a label and a question a reload cut short). It ends with a refresh (`refreshAfterChange` with every cache dropped). Failures toast `<What> failed: <git's first line>.` (a push in a commit says `Push failed`). A step the agent's shell left running toasts `<What> is still running in the background; check the terminal.`, an interrupted one `<What> was interrupted.`; when only the push of Commit & Push is unfinished the commit has landed, so the message is cleared and the toast starts `Committed.`. The smart-commit note is not shown in Amend mode. The selection, the window (anchored to the selected id) and the focus ring work as in Files; `ui.focus` and `ui.scroll` reach them through `focusGit` and `scrollGitList`. Tab state lives in the `gitUi` atom (`message`, `mode`, `ask`, `busy`, `collapsed`, `diffTop`).
- `runHookAware($, root, steps, viaAgentShell)` (in `git.tsx`) runs every git write of the tab. Without hooks it is `runSteps` (argv arrays; the commit message is one `-m` argument). With hooks, steps that fire hooks (`commit`, `push`, `pull`, `merge`, `rebase`, `checkout`, `switch`, `revert`) go through the session's shell tool, read from `$.tool.list()` for each operation: `Bash` whenever it is listed (on Windows too: it is the shell Claude uses there), else `PowerShell`. The shell line holds only git's words and quoted paths, never the message: a commit message is written with `$.fs.write` to `<gitdir>/JEI_COMMIT_MSG` (`rev-parse --absolute-git-dir`) and passed as `-F <file>`; the file is emptied afterwards (the host has no delete), and kept while the commit still runs. The command is `shellLine(['git', '--no-optional-locks', '-c', 'core.quotepath=off', '-C', root, ...step])` (plain words bare, the rest single-quoted for that shell). It is asked first with `$.tool.check` (`deny` fails the step; the first `ask` explains that normal host permissions/review apply), then run with `$.tool.call({ tool, command, description, timeout: 600000 })`. An ordinary deny or error result becomes a `GitError`; a result moved to the background, timed out or interrupted (`backgroundTaskId`, `timedOutAfterMs`, `interrupted`) is not a success: the tab toasts `Commit is still running in the background; check the terminal.` (or Push, Pull, Sync) and keeps the message. Core's environment (`LC_ALL=C`, `GIT_LITERAL_PATHSPECS`, `GIT_TERMINAL_PROMPT=0`, …) cannot be set through the agent's shell, so on a hooks repo git speaks the person's locale there and `isDivergence` may miss a divergence on a non-English locale (Sync then toasts git's line instead of offering Merge and Rebase). Sync passes the same runner to core's `sync`.
- `hosts/claude-code/diff.tsx` draws the diff view: the path header is a plain `Button` keyed `diff-title` (path with a middle ellipsis, then `· staged` / `· working tree` / `· untracked` and `+N −M` while they fit); the body is `Code format="diff"` (`wrap="truncate-end"`, in a box clipped to the window's rows) holding a window of `diffWindow` rows from `gitUi.diffTop`, so a 5,000-line diff never goes to the engine whole (`Code` takes 100,000 characters per drawing and refuses a hunk cut mid-way). A capped diff starts with `Diff truncated at 5,000 lines.` (`warning`). `n`/`p` move the window to the next or previous hunk header (the pane draws its own window, so this sets `diffTop` instead of calling `$.ui.scroll`), `j`/`k` open the next or previous file of the same group, `a` fills the prompt with `reviewText` (8,000 characters at most), `o` opens the file. The shell supplies shared `q` Back for one-level return; `3` still resets the tab (Esc is the host's, ADRs 0009 and 0017). The loaded diff is a module cache dropped by every refresh (`onRefresh` in `activity.ts`).
- The hint line of a letter view (`hintItems` in `pane.tsx`) keeps its letter keys and their labels before its navigation words: when not every item fits, `↑↓`/`enter` go bare, then go, because a letter key only works while its Button is drawn. A plain hotkey Button draws `k: label` and, with an empty label, `k: ` (its trailing space is the gap to the next item); a non-plain one draws `[ label ]` and not its hotkey. So a letter key that loses its label becomes a keycap `[ k ]` (label `k`), and only below the width of tight keycaps a labelless `k: ` strip (`docs/design.md` section 5).
- `hosts/claude-code/theme.ts` maps the design tokens to Claude Code theme keys (`activity.read` `autoAccept`, `activity.write` `claude`, `activity.git` `success`, status colors `warning`/`success`/`error`/`merged`); `muted` is `dimColor`.
- The host does not report the OS: the adapter reads it from the cwd's shape (`platformOf` in `core/shared/paths.ts`: a drive letter or UNC is Windows, `/Users/` macOS, else Linux), and passes Windows paths to the opener with backslashes.
- `classic.CwdChanged` does not run for a person-installed plugin where an organization manages Claude Code; there `cwd` stays the session's start directory.

**Git hooks.** `$.process.run` runs git with repo hooks off. When a repo uses hooks (detected in `core/git/hooks.ts`), hook-firing operations go through Claude Code's shell tool via `$.tool.call`, after `$.tool.check`. See `docs/decisions/0006-hooks-aware-commit-on-claude-code.md`.

**Graph and Branches (v0.2).** `graph.tsx` joins the existing Git list's selection and scroll with collapsible history, explicit Load more, filters, inline files/actions and contextual hints. `branches.tsx` draws locals/remotes, dirty/detached switch/create confirmation, filtering and comparison files. `diff.tsx` supports working, commit and comparison sources, preserving expanded history/branch selection on back and using the same `j/k` file navigation. `history` stores filters, pages, expansion, branch UI and agent hash arrays per repository in session state. Working selection keeps its existing six hint Buttons; a graph commit substitutes `y/a/b/f/t/n`, and non-commit Graph contexts (header, Load more, expanded files/actions) provide `b/f/t/e`. Sync remains reachable on a clean tree below the 60-column header-Button threshold. Expanded Checkout/Revert/link rows remain in the shared arrow/Enter list. Branches has `n/c/f` and the shell provides shared `q` Back. Every applicable key stays drawn at 24 columns and five rows. Hooks include `revert` in addition to the existing operations.

Verified in installed `.claude-plugin/types/claude-code/index.d.ts`: `CoreEngineInterface.ui.copy`, `UiCopyArgs`, `UiCopyResult`, `CoreEngineInterface.session.id`, `ToolCallInput`/`ToolCallEnvelope`, the `tool.call` wrapper/`next`, and `ClassicResult.watchPaths`. The clipboard call passes the render surface and toasts `Copy failed: <reason>.` on failure. A true OSC 52 result cannot prove the terminal accepted it. `watchPaths` is only a `string[]` contract with no directory/recursive guarantee; retain HEAD/index watches, and refs change by other tools refreshes on next snapshot. Snapshots and completed JEI operations drop history/diff caches. Live terminal clipboard, hooks, theme and focus behavior still require manual QA.

The `tool.call` wrapper captures HEAD/reflog evidence before shell execution, pairs core tokens in its own call closure, and observes actual final HEAD. Registries use the documented session id plus resolved repository root. Pending-call counts invalidate overlapping starts even while baseline reads await. A nested mutation guard spans every JEI Git operation and `runHookAware`, suppressing JEI's own shell hooks and ambiguous agent windows until `finally` cleanup. State retains only `AgentCommits.toJSON()` hashes. Bookkeeping errors leave the tool result intact and never rerun its `next` call. Conservative missing marks and unrelated external commits inside a valid window retain the core limitations (ADR 0014).

**Sync review recovery.** Installed Claude Code 2.1.304 declares `tool.check` as a query that executes nothing and asks no classifier. `ToolCallResult` exposes a denied string or `isError` with optional `text` and an unknown stored error result. The runner recognizes the exact missing-request refusal only on these failed channels (including a string stored result), not successful output. A dedicated non-GitError preserves pending steps through core Sync. Its pinned Ask Claude/Cancel question is separate from divergence and root-bound; completed pull is excluded if only push was refused. Ask checks the current cwd's top-level afresh, then calls only `$.prompt.fill({ text, mode: 'insert' })` with separating newlines. A failed fill/root check retains the question; `isFilled: true` clears it. Cancel/q performs no operation. No submit, automatic retry, direct fallback, permission override or configuration change occurs. The installed declarations document that prompt fill can be unavailable under a dialog/headless; a later normal model request still requires the host's authorization. See ADR 0018.

## OpenCode

Target: **OpenCode 2.x only**, minimum **2.0.32**. The 1.x line has no `session.panel` slot. CI type-checks against the latest `@opencode/plugin`.

**Entries.** A package has a server entry (`@opencode/plugin`, `Plugin.define({ id, setup(ctx) })`) and a TUI entry (`@opencode/plugin/tui`, exported as `./tui`). The loader resolves `index`, `tui` and `rpc` in the package folder, which is why the repo root has `index.ts`, `tui.ts` and `rpc.ts`. The RPC contract is `Rpc.define({ id: 'jei', methods, events })` from `@opencode/plugin`. Anything touching files or git runs in the server entry; the TUI may be remote.

| Need | API |
| --- | --- |
| Docked pane | `context.ui.panel.open(name, { presentation })` and `context.ui.slot({ replace/append: 'session.panel', render })`; slot input has reactive `name`, `sessionID`, `width`, `presentation`, `focused` plus `focus()`, `close()`, `toggleFullscreen()` |
| Full-screen views | `context.ui.router.register({ name, render })` |
| Drawing | OpenTUI elements in Solid JSX (peers `@opentui/solid`, `@opentui/core`); colors from `context.theme` and `context.themeMode` |
| Keys and slash command | `context.keymap.layer(() => ({ commands, bindings }))`; a command has `id`, `title`, `bind`, `palette`, `slash`, `run` |
| Dialogs and toasts | `ui.dialog.confirm`, `ui.dialog.select`, `ui.dialog.prompt({ title, value })`, `ui.toast.show` |
| Processes and files | Server entry: `node:child_process` `spawn` with argv arrays, `node:fs/promises` |
| Server and TUI link | Server: `ctx.rpc.register(definition, handlers)` returns a registration with `events.emit`; TUI: `context.client.rpc` |
| Agent activity | Server: `ctx.tool.hook('execute.after')` (and `execute.before`) with `tool`, `sessionID`, `input`, `status`, `result`; events `filesystem.changed`, `vcs.branch.updated` |
| Commit message model | `ctx.generate.text({ prompt, model? })` returns `{ text }`; `prompt` is a string, `model` is `{ providerID, id, variant? }` |
| Storage | `context.storage` in the TUI, `ctx.storage` on the server |

**Foundation.** Built in Tasks 13-14: `nodeHost(generate)` implements the core Host with Node processes and async filesystem calls; `hosts/opencode/rpc.ts` contains the single portable `Rpc.define` contract and `GitSnapshot` wire converters, re-exported by root `rpc.ts`. Root `index.ts` re-exports the server plugin in `hosts/opencode/server.ts`. Its handlers narrow SDK inputs, validate every path under `ctx.location.directory` (the whole batch before changing files), and invoke core services. Methods return objects (`allFiles`: `{ files }`, `generate`: `{ message }`, void: `{}`). The preview schema includes `error`, and core still rejects symlink previews outside the real root. Discard and commit take fresh snapshots; `commitPlan` carries `refusal` while a file is unmerged, and commit throws it before any step; commit validates `approvedSensitive: string[]` and refuses before Git steps when any current sensitive path is absent from that literal approved list. The shell consumes state/events; Files and Git own their actions and dialogs, including confirmation before calling discard.

Verified against installed 2.0.32 types: `Rpc.define` preserves the literal definition; JSON Schema method inputs and outputs infer as `unknown` in the SDK, so consumers must narrow them. `RpcRegistration.events.emit(name, data)` sends events (there is no direct `registration.emit`). `GenerateTextInput` is flat: `ctx.generate.text({ prompt: text, ...(model ? { model: { providerID, id } } : {}) })`; an empty model omits `model` and uses the host default.

**Server lifecycle.** `ctx.rpc.register` and `ctx.tool.hook` are awaited; their registrations have async `dispose()`. `ctx.event.subscribe({ signal })` returns an async iterable whose event has top-level `type` and optional `location.directory`. The server subscribes with its own abort signal and debounces file/branch changes and completed tool writes/git activity by 300 ms. Tool activity passes through `classifyTool`, `insideRel` and `allows(options.activity, kind)`; disabling markers still allows refresh. Unclassified shell commands also refresh, as on Claude Code. Cleanup stops the timer, aborts and awaits the stream, and disposes both registrations, including rollback after failed setup. Background failures are logged; they do not fail an already completed tool call.

**TUI shell.** Built in Task 15: root `tui.ts` re-exports `hosts/opencode/tui.tsx`, which uses `Plugin.define` from `@opencode/plugin/tui` (there is no bare exported `define`). Its additive slot renders only `input.name === 'jei'`. `/jei [tab|path]` uses the shared parser and opens with `{ presentation: 'panel' }`; an empty argument toggles the active session's JEI panel. Ephemeral `storage.memory` preserves pane state and a successful auto-open marker per session through remounts/reloads. The session route is reactive, so `startOpen` waits for a session and runs once there. The panel's second layer is enabled only when `input.focused`, includes core's Esc/back, and changes with the current view. The host removes component key layers on disposal.

The 2.0.32 resolved theme uses nested tokens: `theme.text.base`, `theme.text.muted`, `theme.text.action.primary.base` and `theme.text.feedback.error.base`. The SDK declares `@opencode/theme` as an optional peer; it is absent in this dev install, so those token paths were additionally verified against the published 2.0.32 declarations without changing dependencies. `PanelInput` has width but no height: the root OpenTUI box measures its actual height with `onSizeChange` for short-pane chrome. RPC listeners use `event.data`, return unsubscribe functions and are disposed with the Solid owner. The activity timer stops at the end of its two-second glow and on unmount.

**Files.** Built in Task 16: `files.tsx` draws lazy, directories-first listings through RPC and core's `treeRows`, hidden toggle, fuzzy project filtering (`filterRows`), ancestor reveal (`reveal`), rolled-up Git status (`folderStatus`) and a selection-anchored viewport. The shell's core key layer delegates actions to Files, retains Esc for preview/filter back, and suspends letter/digit commands while the filter input holds focus. An active filter retains its editable row even at heights 2 and 5, alongside at least one result row. Keys keep working when short panels hide chrome. A rejected filter-list RPC shows `Can't list project files.` in the error color, distinct from no matches; reopening the filter or a changed event retries it. Changed events invalidate listings and reload the active preview/filter list; `latest` guards each request group and disposal suppresses late replies. Activity optionally selects/reveals a file while an already open preview keeps its own path. OpenCode's Files, activity and server boundaries share core's `insideRel` guard, which preserves literal filename whitespace while rejecting paths outside the project; `projectRel` remains the trimming helper for typed paths.

Code and Markdown use OpenTUI `code` with the resolved theme's `syntax` tokens, source concealment off, character wrapping and native visual-row scrolling. CSV/TSV use `fitTable`, capped at 200 rows. Image, binary, too-large, empty and error kinds have explicit notice rows; unreadable previews say `Can't read this file.` because RPC carries no OS detail. Image copy is `Image preview is not available in OpenCode.` and binary copy is `Binary file — no preview.`. The RPC has no size field, so too-large copy is `Too large to preview.`.

`colors.ts` names the closest resolved accents in `ACTIVITY_COLORS`: read → `text.feedback.info.base`, write → `text.feedback.warning.base`, git → `text.feedback.success.base`. Visible names blend toward `text.base` in eight 250 ms steps; selected names retain their foreground and their gutter marker fades instead. Touched markers remain dim after the glow. Status letters also use feedback tokens; selection uses `background.action.primary.base`. These tokens were verified in the published 2.0.32 declarations without importing or installing the optional theme peer.

`hand-off.ts` exports `handToAgent(ctx, sessionID, text)`: the editable `ui.dialog.prompt({ title: 'Send to OpenCode', value: text })` sends the confirmed text through the installed promise client's `client.session.prompt({ sessionID, text })`; `undefined` cancels. Mention text comes from `mentionText`, and editor opening uses RPC `open({ rel })`, which answers `{ refused }` for a runnable type with no `editorCommand`; Files and the diff show it as a warning toast. Both use project-relative paths; the TUI never starts a process.

**Git and diff.** Built in Task 17: `git.tsx` narrows the wire snapshot and maps repository paths to literal project-relative RPC paths. The repository header shows branch/dirty, ahead/behind, detached/no-upstream and hooks metadata, busy feedback and clickable Sync. A pinned native `<input>` keeps one editable row even at heights 2 and 5. Click it or activate Edit message to type; `c` opens `ui.dialog.select<CommitMode>` (Commit, Commit & Push, Commit (amend)) and focuses the input after selection. Enter in the input commits the current mode; Esc leaves editing. Letter/digit shortcuts are disabled while editing. Commit, mode, Generate, Sync, group headers and files remain reachable by arrows/Enter when short panels scroll their controls. Empty messages cannot commit.

The installed OpenTUI 0.5.17 input strips CR/LF and defaults to 1,000 characters. JEI therefore keeps the complete generated draft in session memory and gives the input only its first line, with an explicit `maxLength` above the native default. Editing replaces only the subject; the original line separators and body remain stored and are included when Enter submits the complete message. A draft with a body labels the control `Edit subject (body kept)`. Body editing is unavailable in this single-line field; generating again replaces the complete draft. A blank subject cannot commit. The placeholder is `Message (enter to commit on "<branch>")` from 60 columns when it fits, otherwise `Message`. `Nothing staged. Commit stages all changes.` appears only with changes, no staged files, smart commit enabled and a non-amend mode.

`s`/`u` apply to a selected file or group; `d` confirms a file/group discard with `ui.dialog.confirm`, including the untracked deletion count (one untracked file reads `Delete the untracked file <path>?`, as on Claude Code). A plan with `refusal` (an unmerged file) shows `Resolve conflicts first.` as a toast and asks nothing. Wide group headers also expose clickable Stage all, Unstage all and Discard all. Commit reads `commitPlan`, lists every sensitive path in a confirm dialog, then replans after approval and compares the current sensitive paths with the exact approved list. A new path requires another complete-list confirmation and replan. The commit RPC carries `approvedSensitive` (an empty list for normal commits), which the server checks against its own fresh plan before any steps run. If that check refuses, the TUI requests a fresh plan, shows the complete list and requires confirmation before one retry; cancel sends no retry. A session-memory busy guard covers dialogs, mutations and the immediate state refresh, including tab remounts; the draft message and mode also survive remounts. A successful commit clears only the submitted draft, retaining newer edits. Failures retain the message and show a bounded first-line error. Diverged Sync opens `ui.dialog.select<'merge' | 'rebase' | 'ask'>`; Merge/Rebase call the explicit choice and Ask uses `handToAgent`. Mutations refresh state immediately, including failed steps that may have partially changed the repository. No TUI process or filesystem API is used; hooks run through the existing server Host.

`diff.tsx` validates RPC replies, uses core `diffWindow` for hunk positions and renders typed hunk lines with `theme.diff.text.{added,removed,context,hunkHeader}` and `theme.diff.lineNumber.text`. These paths were verified against the published optional theme declaration at version 2.0.32. Content wraps by terminal cells, including wide characters; continuation gutters use `│`. Both line numbers appear from 100 columns, the new number from 60, and gutters drop below that. Scroll anchors retain the logical row and character offset through rewrapping. `n`/`p` jump hunks, `j`/`k` move within the source group, `o` uses RPC open, `a` uses core `reviewText`/`toUnifiedText` through `handToAgent`, and `q`/Back (also Esc/header click) return to the retained parent selection. Empty, binary, error and 5,000-line truncation states are explicit. Stable target/project memos and `latest` prevent older selections, changed events and disposed loads from repainting a newer diff.

**Known gaps.**
- No API to insert text into the user's prompt. Mention and send open an editable `ui.dialog.prompt` prefilled with the text, then send it with `client.session.prompt({ sessionID, text })`. Esc cancels.
- Installed plugin/client/protocol 2.0.32 exposes no LSP query API; Symbols is approximate only. The client lsp field configures servers and is not a query method.
- No diff element: JEI renders `core`'s parsed hunks line by line with theme colors.

**Keys.** `keymap` allows chords, but JEI uses the same single-letter and digit keys as Claude Code. Never bind `ctrl+n` or `ctrl+p` (reserved by OpenCode's dialogs). On narrow terminals OpenCode shows panels full screen.

**Tools.** Tool names are read from `ctx.tool.list()` at runtime; `core/` classifies a call by tool id first and by input shape (a `filePath` or `path` field, a `command` field) as fallback.

**Git hooks.** Git runs as a normal process, so repo hooks fire; nothing special is needed.

## Both hosts

Every view renders at 40 columns; git always runs with `--no-optional-locks` and `GIT_OPTIONAL_LOCKS=0`; no shell strings; agent labels use the host's name (Ask Claude, Ask OpenCode). Behavior differences are limited to those listed above and are recorded in `PRD.md` §13.

## OpenCode Search and Symbols (0.3)

Rechecked installed `@opencode/plugin` 2.0.32 `dist/promise/plugin.d.ts`, `tool.d.ts`, client and protocol declarations: no supported LSP/symbol query API is exported. Client `generated/types.d.ts` has LSP configuration only. Symbols is approximate throughout.

`search.tsx` and `symbols.tsx` use existing native input, theme, selection window, session memory and key-layer patterns. Search submits its draft on Enter; flag-driven refreshes debounce 150 ms; the server batches at 200 matches or 100 ms. `RpcCallContext` supplies signal/error only; stateful calls carry sessionID explicitly. Pending ordinary RPC calls use the installed second `{signal}` argument, while persistent streams use searchCancel and server cleanup. Listeners unsubscribe on unmount and late generations cannot navigate or refill busy state. Result/call-child Send resolves the actual selected symbol.

Search matches/done first compare the installed native RPC event's `location.directory` with the current cwd, before parsing its data or changing state. Session/id alone are insufficient when roots reuse a serial. The keyed pane body uses an argument-taking child: installed Solid Show treats only functions with positive arity as keyed render callbacks, so this detail is required for actual session/root remount. Quick Open candidates/revision live in that session/project memory, survive preview Back, and refresh after invalidation. Refresh failures remain visible through an error toast even with cached rows. Compact target-dependent controls retain the last selected current data subject and never substitute an unrelated result/file.

Each Pane lifetime invalidates Quick Open once per session/project so changes missed while closed cannot leave a valid-looking stale cache; remounting Search for preview Back within that Pane still reuses it. The installed RPC client rethrows remote errors as plain `{type,message,data?}` objects. Search/Symbols accept their string message, preserve the first line and existing fitting, and retain generic fallback text for unknown error shapes.

Search and Quick Open retain separate query text. Esc/Cancel in query or globs leaves editing while the existing Search continues; preview/unmount cancels it with `Search canceled.`. Ordinary changed events refresh Files/Quick Open while retaining Search results/selection. Successful own replacements refresh Files immediately and rerun Search on review Back. Background Symbols outline loading uses independent cancellation/loading state, so activity/changed reloads cannot cancel user References/Calls or block Find. Disposal cancels both scopes.

Replacement RPC owns reviewed snapshots per session/project and validates the complete selected subset before writes. Per-file apply preserves known written/skipped results plus optional error after a later write exception; remaining files survive, and changed is emitted even after a possible partial write. Outline returns `{file,nodes}` to distinguish unsupported regular files from directory/missing selections; supported-file read failures are explicit. Recursive schemas use installed-supported top-level `$defs`, with no pattern. TUI relative-path checks preserve colon/whitespace names without claiming to know the remote OS; native and realpath guards stay server-side.

Search/Symbols hints remain at five rows. Submit/Cancel releases letter/digit shortcuts. Shared preview targets route across tabs and show a native gutter marker in a bounded source window, including delimited raw text; ordinary wrapping/tables remain. See ADR 0022 and the distinct automated/live evidence in testing and QA.

Explicit target previews initialize at the clamped source line after text arrives; refreshing the same relative-path/target-line pair preserves manual scrolling. Both hosts use shared replacement Ask text with complete locations/omission counts, and shared Search/review budgets and whole-review refusals from ADR 0023.
