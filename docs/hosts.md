# Hosts

> Purpose: verified API facts, limits and version floors for Claude Code mods and OpenCode 2.x plugins · Status: current · Last reviewed: 2026-10-19

Source: `PRD.md` §4.2 to §4.4, verified in October 2026. Both APIs are young; a host's exported types are the contract. If a fact here turns out wrong, fix this file and say so in the commit.

## Claude Code

Minimum version **2.1.302**. CI also runs against the latest release. The mod API is early access.

**Mod rules.** A hooks module has no Node, no DOM, no `WebAssembly`, no `eval` and no dynamic `import()`. Imports must stay inside the plugin folder (which is why the whole repo root is the plugin and `core/` ships with it). Relative imports keep their `.ts` extension. `userConfig` values in `plugin.json` are strings; on/off settings are `"on"`/`"off"` pickers.

**Types.** `.claude-plugin/types/` is laid by Claude Code, gitignored and never committed. The plugin's own state contract is `types/index.d.ts`.

| Need | API |
| --- | --- |
| Docked pane | `$.ui.open({ id, title })`, rendered on `ui.render` for `{ component: 'Pane', requestId }` |
| Elements | `$.ui.resolve(e)` gives `Box`, `Text`, `Button`, `Input`, `Select`, `Code`, `Markdown`, `Image`, `Raster` |
| Colored diffs | `Code` with `format: 'diff'` (plain if the text is not a valid unified diff) |
| Run git or rg | `$.process.run(argv, { cwd, timeoutMs, stdin })` (4 MiB stdout cap, 30 s default timeout); `$.process.spawn` to stream |
| Files | `$.fs.read`, `write` (UTF-8, 4 MiB), `list`, `exists`, `stat`, `ancestors` |
| Agent activity | `tool.call` hooks on `Read`, `Edit`, `Write`, `NotebookEdit`, `Grep`, `Glob`, `Bash`, `PowerShell` |
| Disk and cwd changes | `classic.FileChanged`, `classic.CwdChanged`, `watchPaths` from `classic.SessionStart` |
| Text into the prompt | `$.prompt.fill({ text, mode: 'insert' })` |
| Commit message model | `$.model.complete({ model, prompt })` on the session's own client; no API key |
| State | `$.state` (session, drives redraws) declared in `types/index.d.ts`; `$.store` across sessions |
| Slash command | `$.command.register` and `command.run` |
| LSP (milestone 0.4) | `$.tool.call({ tool: 'LSP', ... })`; the result is formatted text, may need a permission; check first with `$.tool.check` |

**Keys.** A pane receives keys only through its `Button`s: a `hotkey` is one digit or one lowercase letter. Tab and arrows walk the focus ring; Esc returns to the prompt. There is no raw key event, so the single-key rule in `core/keys.ts` follows from this.

**Layout and surfaces.** Docking beside the transcript needs `/tui fullscreen`; a pane opened unasked seats from about 110 to 144 columns, inline below that. Body width is `e.props.bodyColumns` (expect 40 to 60). The terminal is first class; the Desktop app also draws mod panes (`e.surface === 'desktop'`), so every tree must be valid there and work by click. Mods do not load in the Desktop app's WSL sessions, the VS Code chat panel or `claude -p`. Mouse works only in the fullscreen layout.

**Adapter structure.** Status: current for the pane shell, Files and Git (plan Tasks 10, 11, 12).
- `hooks/register.tsx` is wiring only: `session.start` registers `/jei`, writes `cwd` and the opening tab, and arms the auto-open only on a fresh session (the pane state was never written), so a hot reload never reopens a pane the person closed; a pass-through `ui.render` hook on `PromptHint` opens the pane unasked once, only when armed, `options.startOpen` and `e.viewport.isFullscreen` is true (session start knows no viewport); `command.run` for `jei` answers its own command (`JEI opened.`, `JEI closed.`, `JEI opened on <Tab>.`) and opens with `focus`. Bare `/jei` closes only a pane that is placed and shown, otherwise brings it forward. An open that is not placed answers `JEI is open but not shown yet: <reason>.`, a rejected open or close answers `JEI could not open: …` / `JEI could not close: …`. `/jei <path>` resolves the path against `cwd` (`projectRel`): absolute or relative, outside the project or escaping with `..` answers `That path is outside the project.` and changes nothing; `classic.CwdChanged` updates `cwd` (its `.catch` passes the event on); `ui.render` on `{ component: 'Pane', requestId: 'jei' }` calls `renderPane`.
- `hosts/claude-code/state.ts` declares the atoms (`pane`, `cwd`, `activity`, `git`, `tree`, plugin `jei`) and the accessors other files use (`readPane`, `updatePane`, `setCwd`, ...). `claude plugin validate` traces a state call only to an atom declared in the same file, and follows `$` across an import only into a function declaration, so state calls live in `state.ts` and accessors are `function` declarations. A matcher's `requestId` must be a literal.
- `types/index.d.ts` is self-contained (no imports) and repeats core's shapes as JSON; `state.ts` fails to compile if they drift. `GitSnapshot`'s count `Map`s are stored as records (`gitState`), because state is JSON.
- `hosts/claude-code/host.ts` is `claudeHost($, platform)`: `$.process.run` (no signal support: an aborted call never starts; a truncated stdout throws `Output too large: <argv>` rather than handing core a partial list), `$.fs.list`, `$.fs.stat(path, { resolve: true })` (no `realPath` gives `null`: fail closed), `$.fs.read` (bytes mode for `readHead`), `$.model.complete` (model `haiku` when empty, 30 s timeout; no answer throws).
- `hosts/claude-code/pane.tsx` draws the shell from `bodyColumns` and `scroll.bodyRows` on every render. Tabs are `Button`s keyed `tab-1`..`tab-4` with hotkeys `1`..`4`, the current one `variant="primary"` and bold (non-plain, so `primary` shows and the hotkey mark is not doubled). The terminal draws each as `[ 1 Files ]`, so the adapter calls core's `tabBar` with 4 cells of chrome per tab; on this host the 2-space gap therefore often drops to 1 (at 24 columns: `[ 1 ] [ 2 ] [ 3 ] [ 4 ]`). A `Text` takes no `key`, so named rows (`rule`, `header`, `hint`, `body-<n>`) are keyed `Box`es holding one `Text`.
- `hosts/claude-code/files.tsx` (plan Task 11) draws the Files tab for `pane.tsx`: header (root name, or the filter `Input` after `f`), a body window anchored to the selected row's id (1 row of context from 5 body rows, kept across resizes), and the letter actions. Rows are a keyed gutter `Box` (`glow-<rel>` while glowing, `mark-<rel>` once touched, else `gut-<rel>`) and a plain `Button` keyed `row-<rel>` holding the name `Text` and a right-aligned status `Text`. Enter on a folder toggles it, on a file opens the preview (`Code`, `Markdown` with `m` for source, a `fitTable` text table for CSV/TSV, `Image` for PNG on the terminal, else a notice). The preview draws the file named by the `preview` atom (`rel`), so follow-agent never changes it. Its header is a plain `Button` keyed `back`; Esc never reaches a pane (ADR 0009). The hint line stays down to 3 rows on Files (bare below 10), because the letter keys are its Buttons' hotkeys. `a` calls `$.prompt.fill({ text: mentionText([rel]), mode: 'insert' })`; `o` runs `openFile` and toasts `Can't open <name>: <first line>.` on failure. Listings (`listDir`), the filter's file list (`allFiles`) and the current preview (only one is kept; opening a preview clears it) are module caches read while drawing (a draw may read but never write state). `forgetPaths` drops the root's and every ancestor's listing, the path's own listing and those below it; `forgetAll` drops every listing of the root. A failed listing draws `Can't read this folder.` and is dropped on the next toggle or refresh, never retried per frame; a failed preview draws `Can't read this file: <first line>.` The adapter remembers the element `ui.focus` last landed on; the selected row is inverted unless the pane holds the keyboard and the ring is on that row. `ui.focus` on a `row-` element selects it; `ui.scroll` moves the selection (tree) or the first line (preview) and answers `{}` because the pane draws its own window.
- `hosts/claude-code/activity.ts` (`registerActivity`): `tool.call` awaits `next(e)` first, returns its result, and does the bookkeeping unawaited: it classifies (`classifyTool`; Grep and Glob add their result's `filenames`), maps paths with `projectRel` (outside the project is ignored), touches the `activity` atom when `allows(options.activity, kind)`, and with `followAgent` reveals and selects the first path. Writes and git actions schedule one refresh 300 ms after the last change, and at most 1.5 s after the first of a burst (`$.clock.after`). A `Bash` or `PowerShell` call that is not a pure read (or that JEI cannot classify) refreshes everything. A refresh drops the caches, re-reads git through `latest`, re-reads the file list only while the filter is open (otherwise drops it), and bumps `tick`. The activity log keeps the 500 most recent touches. While a row glows a `$.clock.every(250)` bumps `tick` and cancels itself once nothing glows. A pass-through `classic.SessionStart` adds the git index and HEAD (from `git rev-parse --absolute-git-dir`) to `watchPaths`, so `classic.FileChanged` also fires for commits, stages and checkouts made outside the agent's tools; it schedules the same refresh (git always, the folder when the path is in the project). `classic.CwdChanged` starts the git refresh without awaiting it. The validator follows `$` only into top-level function declarations, so the timers are module-level.
- `hosts/claude-code/git.tsx` (plan Task 12) draws the Git tab for `pane.tsx`. Header: the repository row (`acme-app  ⎇ main*  ↓2 ↑1  hooks  Sync`): the repo name from 100 columns, `Sync` (a plain `Button` keyed `sync`) from 60; past that the hook marker, then a busy label, drop, the branch shortens to 10 cells, then `↓↑` drops. A detached HEAD reads `⎇ (detached a41f9c2)` and no upstream `no upstream`, both `warning`. Not a repository: `This folder is not a git repository.` and an `Initialize repository` Button (`init`). Body: an open question pinned on top (a muted rule, one line, its Buttons), then the message `Input` (`message`; placeholder `Message (enter to commit on "main")` from 60 columns when it fits, else `Message`; Enter commits), a row of Commit (`commit`, primary, labelled with the mode; with an empty message a dim `[ Commit ]` keyed `commit-off` that cannot be pressed), the mode `Select` (`commit-mode`: Commit, Commit & Push, Commit (amend)) and `✦ Generate` (`generate`), wrapped onto more rows when narrow, then the Staged and Changes groups. A group header is a plain `Button` (`group-staged`, `group-changes`) that collapses it, with `Unstage all` / `Stage all` / `Discard all` (`unstage-all`, `stage-all`, `discard-all`) when they fit and its count at the right. A file row is a plain `Button` (`staged-<path>`, `change-<path>`): status letter, basename, the folder from 60 columns, `+12 −3` right-aligned in a column as wide as the widest visible count from 32. Enter opens the diff. Keys (hint Buttons): `s` stages the selected change (or the whole group on its header), `u` unstages, `d` asks to discard, `c` commits, `g` generates, `e` syncs. Discard (one or all) always asks first: `Discard` / `Cancel` (`confirm-discard`, `confirm-cancel`), and nothing runs until `Discard`. A commit whose files look sensitive asks `These files look sensitive: .env` with `Commit anyway` / `Cancel`; a diverged Sync asks with `Merge` / `Rebase` / `Ask Claude` / `Cancel` (Ask Claude fills the prompt). An operation shows its label (`Committing…`, `Syncing…`, `Generating…`) in the repository row, refuses a second one meanwhile, and ends with a refresh (`refreshAfterChange` with every cache dropped). Failures toast `<What> failed: <git's first line>.` (a push in a commit says `Push failed`). The selection, the window (anchored to the selected id) and the focus ring work as in Files; `ui.focus` and `ui.scroll` reach them through `focusGit` and `scrollGitList`. Tab state lives in the `gitUi` atom (`message`, `mode`, `ask`, `busy`, `collapsed`, `diffTop`).
- `runHookAware($, root, steps, viaAgentShell)` (in `git.tsx`) runs every git write of the tab. Without hooks it is `runSteps` (argv arrays; the commit message is one `-m` argument). With hooks, steps that fire hooks (`commit`, `push`, `pull`, `merge`, `rebase`, `checkout`, `switch`) go through the session's shell tool, read once from `$.tool.list()`: `Bash`, else `PowerShell`. The command is `shellLine(['git', '-C', root, ...step])` (plain words bare, the rest single-quoted for that shell), asked first with `$.tool.check` (`deny` fails the step; the first `ask` toasts why and suggests allowing `Bash(git *)`), then run with `$.tool.call({ tool, command, description })`. A deny or an error result becomes a `GitError`. Sync passes the same runner to core's `sync`.
- `hosts/claude-code/diff.tsx` draws the diff view: the header is a plain `Button` keyed `back` (path with a middle ellipsis, then `· staged` / `· working tree` / `· untracked` and `+N −M` while they fit); the body is `Code format="diff"` holding a window of `diffWindow` rows from `gitUi.diffTop`, so a 5,000-line diff never goes to the engine whole (`Code` takes 100,000 characters per drawing and refuses a hunk cut mid-way). A capped diff starts with `Diff truncated at 5,000 lines.` (`warning`). `n`/`p` move the window to the next or previous hunk header (the pane draws its own window, so this sets `diffTop` instead of calling `$.ui.scroll`), `j`/`k` open the next or previous file of the same group, `a` fills the prompt with `reviewText` (8,000 characters at most), `o` opens the file. Back is the header Button or `4` (Esc is the host's, ADR 0009). The loaded diff is a module cache dropped by every refresh (`onRefresh` in `activity.ts`).
- The hint line of a letter view keeps its letter keys before its navigation words: when not every item fits, `↑↓`/`enter` go first, because a letter key only works while its Button is drawn. A bare hotkey Button draws `k: `, whose trailing space is the gap to the next item.
- `hosts/claude-code/theme.ts` maps the design tokens to Claude Code theme keys (`activity.read` `autoAccept`, `activity.write` `claude`, `activity.git` `success`, status colors `warning`/`success`/`error`/`merged`); `muted` is `dimColor`.
- The host does not report the OS: the adapter reads it from the cwd's shape (`platformOf` in `core/shared/paths.ts`: a drive letter or UNC is Windows, `/Users/` macOS, else Linux), and passes Windows paths to the opener with backslashes.
- `classic.CwdChanged` does not run for a person-installed plugin where an organization manages Claude Code; there `cwd` stays the session's start directory.

**Git hooks.** `$.process.run` runs git with repo hooks off. When a repo uses hooks (detected in `core/git/hooks.ts`), hook-firing operations go through Claude Code's shell tool via `$.tool.call`, after `$.tool.check`. See `docs/decisions/0006-hooks-aware-commit-on-claude-code.md`.

## OpenCode

Target: **OpenCode 2.x only**, minimum **2.0.32**. The 1.x line has no `session.panel` slot. CI type-checks against the latest `@opencode/plugin`.

**Entries.** A package has a server entry (`@opencode/plugin`, `Plugin.define({ id, setup(ctx) })`) and a TUI entry (`@opencode/plugin/tui`, exported as `./tui`). The loader resolves `index`, `tui` and `rpc` in the package folder, which is why the repo root has `index.ts`, `tui.ts` and `rpc.ts`. The RPC contract is `Rpc.define({ id: 'jei', methods, events })` from `@opencode/plugin`. Anything touching files or git runs in the server entry; the TUI may be remote.

| Need | API |
| --- | --- |
| Docked pane | `context.ui.panel.open(name, { presentation })` and `context.ui.slot({ replace/append: 'session.panel', render })`; slot input has reactive `name`, `sessionID`, `width`, `presentation`, `focused` plus `focus()`, `close()`, `toggleFullscreen()` |
| Full-screen views | `context.ui.router.register({ name, render })` |
| Drawing | OpenTUI elements in Solid JSX (peers `@opentui/solid`, `@opentui/core`); colors from `context.theme` and `context.themeMode` |
| Keys and slash command | `context.keymap.layer(() => ({ commands, bindings }))`; a command has `id`, `title`, `bind`, `palette`, `slash`, `run` |
| Dialogs and toasts | `ui.dialog.confirm`, `ui.dialog.select`, `ui.dialog.prompt({ title, value })`, `ui.toast.show` |
| Processes and files | Server entry: `node:child_process` `spawn` with argv arrays, `node:fs/promises` |
| Server and TUI link | Server: `ctx.rpc.register(definition, handlers)` returns a registration with `emit`; TUI: `context.client.rpc` |
| Agent activity | Server: `ctx.tool.hook('execute.after')` (and `execute.before`) with `tool`, `sessionID`, `input`, `status`, `result`; events `filesystem.changed`, `vcs.branch.updated` |
| Commit message model | `client.generate.text({ prompt: { prompt, model? } })` returns `{ text }` |
| Storage | `context.storage` in the TUI, `ctx.storage` on the server |

**Known gaps.**
- No API to insert text into the user's prompt. Mention and send open an editable `ui.dialog.prompt` prefilled with the text, then send it with `client.session.prompt({ sessionID, text })`. Esc cancels.
- No LSP or symbol call in the 2.x client, so Symbols is approximate only there (milestone 0.4; re-check then).
- No diff element: JEI renders `core`'s parsed hunks line by line with theme colors.

**Keys.** `keymap` allows chords, but JEI uses the same single-letter and digit keys as Claude Code. Never bind `ctrl+n` or `ctrl+p` (reserved by OpenCode's dialogs). On narrow terminals OpenCode shows panels full screen.

**Tools.** Tool names are read from `ctx.tool.list()` at runtime; `core/` classifies a call by tool id first and by input shape (a `filePath` or `path` field, a `command` field) as fallback.

**Git hooks.** Git runs as a normal process, so repo hooks fire; nothing special is needed.

## Both hosts

Every view renders at 40 columns; git always runs with `--no-optional-locks` and `GIT_OPTIONAL_LOCKS=0`; no shell strings; agent labels use the host's name (Ask Claude, Ask OpenCode). Behavior differences are limited to those listed above and are recorded in `PRD.md` §13.
