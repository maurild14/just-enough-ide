# Testing

> Purpose: which tests exist, which runner runs them, and what every view must prove · Status: current · Last reviewed: 2026-10-20

Source: `PRD.md` §8.1 and `docs/design.md` §10. Run `bun run test`, `bun run typecheck` and `bun run check:docs` before finishing.

## Two runners, two names

| Pattern | Runner | Where | Command |
| --- | --- | --- | --- |
| `*.spec.ts(x)` | `bun test` | `core/`, `hosts/opencode/` | `bun run test`, `bun test <file>` |
| `*.test.ts(x)` | `claude plugin test` | `hosts/claude-code/` only | `bun run test:claude` |

Never mix them: `claude plugin test` loads every `*.test.ts` in the plugin folder, so a stray one elsewhere breaks it. The script `bun run test` runs `bun test ./core ./hosts/opencode`. Specs may import `bun:test` and `node:*`; the `core/` purity rule binds non-spec files. Most tests live in `core/`.

## What is tested where

- **`core/`** (`*.spec.ts`): parsers (git status, diff), pane reducer, key map, paths (including `C:\` and `/` forms), argv splitting, fuzzy ranking, activity and shell-read classification, commit planning, hook detection, sensitive paths, preview classification. Pure functions with fixture inputs.
- **OpenCode adapter** (`*.spec.ts(x)`): `host.spec.ts` runs real processes and temp files, verifies shell-free hidden spawning, byte limits, missing files, model forwarding, cwd/env/stdin, exit failures, timeouts and cancellation before spawning. `rpc.spec.ts` checks JSON snapshot round trips (including binary counts), the method surface, path errors and error previews. `server.spec.ts` drives the package entry with a fake host context, captured RPC handlers/tool hook, async iterable events and real temp repositories. It checks state/staging, Files envelopes and editor opening, every path boundary and atomic batch rejection, symlink previews, literal git paths and diffs, fresh discard/commit status, sensitive approval, flat model input, init/sync, direct repository hook failure, activity filtering, 300 ms debounce with fake timers, location isolation and async cleanup/rollback. OpenTUI view tests with `testRender` and `captureCharFrame` (Tasks 15-17) follow.
- **Claude Code adapter** (`*.test.tsx`): the Claude Code testing kit mounts the pane on both the `terminal` and `desktop` surfaces and drives it; process answers are mocked. `bun run validate` (`claude plugin validate .`) must report no refusals.
  How kit tests run: `claude plugin test .` loads the plugin with its manifest defaults (or `test(name, { options }, body)`), and each test gets the engine's `$` and an `on` whose hooks sit beneath the plugin. Nothing else answers beneath: a test that makes the plugin call `$.ui.open`, `$.ui.close`, `$.ui.panes` or `$.process.run` answers it with `on('ui.open', () => ({ value: ... }))` and the like, or the call fails naming the event. `$.state` is answered by the kit. `$.ui.mount({ plugin: 'jei', surface, component: 'Pane', props, requestId: 'jei' })` draws the pane; `find`/`findAll` match by `type`, `key` and shown `text`, `press({ key })` presses a Button, `drawn()` returns the tree. The kit never paints, so width tests (`hosts/claude-code/pane.test.tsx`) measure the returned tree: a column `Box` stacks lines, a row `Box` joins children with its `gap`, a terminal `Button` adds 4 cells (`[ ` and ` ]`), each width counted with `cellWidth`. Loop every body over `['terminal', 'desktop'] as const`. The shared measurer is `hosts/claude-code/measure.ts` (a plain `Button` is its label, plus `k: ` with a hotkey); its `drawnLine` paints one row as the terminal would (`[ k ]`, `k: label`, a `Select` as `option ▾`) and `findKey` finds a keyed element in `drawn()`, so hint and commit-row tests compare exact lines. Answer `$.fs.*` with `on('fs.list', ...)` and kin: the kit hands them native absolute paths (a drive letter on Windows), so fixtures normalize them; a failure is answered `{ deny: '...' }` (a thrown hook is skipped, not a failure). Register every hook beneath the plugin (`tool.call` included) before the test's first `$` call; `mock.clock(on, { now })` drives the shimmer and the debounce. State outlives a drawing within a test, so a loop over surfaces must undo what it toggles. A test's `$.ui.focus` takes the whole `ui.focus` input (`component`, `requestId`, `plugin`, `element`, `origin`) and needs `on('ui.focus', () => ({}))` beneath. `hosts/claude-code/files.test.tsx` covers the Files tab; fixtures it changes mid-test (`TREE`) are restored in `finally`. `hosts/claude-code/git.test.tsx` covers the Git tab and the diff view: a fixture repo (`repo()`: branch, upstream, ahead/behind, hooks, porcelain v2 records) answers `process.run` by argv, `model.complete`, `tool.list`, `tool.check` and `tool.call` are answered beneath (`{ value }` for the first two calls, the verdict and the tool result as they are for the last two), and a test may change the fixture and re-run `classic.CwdChanged` to refresh. `ui.input({ key, text, kind })` types into the message field and `ui.select({ key, value })` picks the commit mode; a mode a test changes is set back before it ends.

`hosts/opencode/pane.spec.tsx` drives the package's TUI entry with a fake Context at the host boundary and the real OpenTUI `testRender` renderer. It captures character frames and styled spans, invokes the registered command/bindings, and covers tab styling, Search/Symbols placeholders, requested paths, focus, Esc/back, once-per-session auto-open, live resize at 24/40/80/120 columns and 5/10/24 rows, stale RPC replies, malformed data, the conditional activity timer, preservation of live activity across delayed same-file replies with equal clocks or clock skew in either direction, and cleanup with a pending reply. The fake storage implements the SDK's draft mutation semantics with Solid `produce`. Browser DOM verification cannot exercise this terminal surface; these renderer checks compensate for that limitation, and real-host paint remains a manual check.

`hosts/opencode/files.spec.tsx` drives Files through that same public TUI entry, registered bindings, a fake RPC and native input events. It covers directories-first expansion/collapse, hidden/ignored filtering, fuzzy ranking, no-match activation, highlighted code and literal Markdown source, padded CSV/TSV with the 200-row cap, every notice including `error`, mention confirm/edit/cancel, relative editor opening, status letters/colors and folder roll-up, activity colors/fade, follow-agent on/off and preview isolation. Tests capture real frames/spans at widths 24/40/80/120 and heights 2/5/10/24, including every preview kind, wrapped-content scrolling, stale listings/previews and changed-event invalidation. The full preview matrix has a 20-second test timeout because it paints every combination.

Task 16 review regressions also type into the filter at heights 2 and 5 while checking shortcut suppression, preserve distinct leading-space siblings through preview/mention/open/filter and activity, and distinguish failed file-list requests from no matches with retry and changed-event recovery. `core/shared/paths.spec.ts` covers literal whitespace and rejected escapes in `insideRel`; the server specs verify literal-path preview and activity delivery across the RPC boundary.

`hosts/opencode/git.spec.tsx` exercises the public TUI entry, registered exact bindings, native input and mouse events, fake RPC and real OpenTUI frames/spans. It covers initialization, metadata, group counts/actions, literal and option-like paths, discard/sensitive/mode/divergence/review cancel branches, generated and edited messages, all commit modes, empty-message and duplicate-submit/click guards, native focus suppression, draft/mode/busy retention across tab remounts, direct mutation refresh, stale state/diff responses, errors and malformed replies. The width/height matrix is 24/40/80/120 by 2/5/10/24; wrapped wide-character hunks retain position through resize. Unreadable preview coverage: `core/files/service.spec.ts` makes `readHead` return `null` for an existing file and expects `error`, while missing, directory and rejected paths stay `empty`. `hosts/claude-code/files.test.tsx` denies a fixture read and verifies the generic error notice on terminal and desktop at 24, 40, 80 and 120 columns. A caught exception with a message keeps the detailed notice; a null-only Host cannot expose the OS reason.

- The sample repo is `acme-app`; authors are `Ana Rivera <ana@example.com>` and `Leo Park <leo@example.com>`. No real names, emails, paths or projects.
- Text fixtures live in `test/fixtures/` (git porcelain samples in `git/*.txt`, diffs in `diff/*.diff`, later LSP outputs). A change in a tool's output format should fail a fixture test, not users.
- Git fixtures (`test/fixtures/git/status-*.txt`) are real `git status --porcelain=v2 -z --branch --untracked-files=all` output, generated once from a throwaway `acme-app` repo (local identity Ana Rivera, `commit.gpgsign false`, a bare repo as `origin`) kept outside this repo. They keep their raw NUL separators, so `.gitattributes` marks `test/fixtures/**` as `-text` and git never rewrites them. Check a new fixture holds no machine path or username before committing. Cases a fixture cannot reach cheaply (every unmerged code, `?` and `!` records, a newline in a path) are inline strings in the spec.
- The **fake host** (in `test/`) implements `Host` over a temp directory, with real `git` for git specs and scripted answers where a test needs them. Specs create their temp repos fresh and delete them.
  `test/fake-host.ts` exports `FakeHost` (spawns argv with `windowsHide`, never a shell; every `GIT_*` variable of the ambient environment is dropped and a per-process empty global git config is used (removed by `cleanup`), so runs are deterministic; `calls` records argv, `completeReply` scripts `complete`), `makeRepo(files, commits)` (temp `acme-app` on `main`, local identity Ana Rivera, `commit.gpgsign false`, `core.autocrlf false`), `makeTemp`, `configure` (a second clone authored by Leo Park) and `cleanup`, which every spec calls in `afterEach`. Importing it sets a 60 s default test timeout (`setDefaultTimeout`): a real-git spec spawns dozens of git processes, and under load the 5 s default timed one out, whose leftover git calls then failed the next spec after `cleanup` removed its repos. Heavy Claude Code kit sweeps pass `{ timeoutMs: 60_000 }` for the same reason. Temp repos live under the OS temp folder.

## Width and height matrix

Every view is rendered as a snapshot at widths 24, 40, 80 and 120 (200 as a smoke test) and heights 10, 24 and 5, in all three glyph sets, and asserts the checklist in `docs/design.md` §10: no line wider than the pane, exact height, selected row visible, status letters present, right-aligned columns, truncated paths keep the basename, `NO_COLOR` still distinguishes states, no raw color values outside `theme.ts`. A resize sequence (120, 24, 10 rows, 120) must return the same selection and a final output equal to a fresh render. Status: draft — built in milestone 0.1 (plan Tasks 8, 11, 12, 16, 17).

## Manual QA

The Claude Code v0.2 `graph.test.tsx` and `branches.test.tsx` use the native terminal/desktop kit at 24/40/80/120 columns and five-row resize. They exercise shared-list focus, expansion, commit/compare diffs and `j/k/back`, full-hash clipboard delivery/failure, Ask text, supported URL opening, checkout cancel/confirm, merge refusal, hook-aware revert, contextual create, author/branch filters, explicit paging, fetch failure and missing comparison base. Attribution cases cover an agent commit, JSON persistence, session/repository separation, overlapping windows, direct/hooked JEI commits, an agent window starting during a held JEI mutation, and evidence failure without changing the tool result.

`history-fixture.ts` scripts Git wire outputs and native host calls; Claude's kit provides no real process implementation and its runtime cannot import Node/Bun or the real-process fake host. Actual Git behavior is checked by the existing real-Git core service specs using `test/fake-host.ts`, including merge refusal, exact refs, dirty-file preservation, history diffs, reflog creation evidence and command execution. This split is explicit: kit tree/action assertions are not live terminal/hook/clipboard verification. `files.test.tsx` settles the mock clock before its initial status assertion because cwd snapshot refresh is deliberately asynchronous.

What the kits cannot see (real paint, real terminals, a real agent) is checked by hand on both hosts before each release, on Windows and one of macOS or Linux. The checklist is `docs/qa.md`.

They verify pending pull/push and chosen strategy, no retry/direct fallback or submit, separated insertion preserving an existing draft, failed fill, Cancel/q, a stale Git snapshot beside a changed current cwd, ordinary denials/Git errors/divergence/background/interruption, and successful output containing a quoted refusal. ## CI

`.github/workflows/ci.yml` runs on every push to `main` and every pull request: `bun run test` on Ubuntu, macOS and Windows; `bun run typecheck` (core + OpenCode); `bun run check:docs`; `claude plugin validate` and `claude plugin test` on Ubuntu; and a gitleaks scan of the full history. The Claude Code job is `continue-on-error` because the CLI may need a signed-in account in CI, so run `bun run validate && bun run test:claude` before every release. The local `typecheck:claude` script needs types Claude Code lays at `.claude-plugin/types/` (gitignored, never committed), so CI checks the Claude Code half with `claude plugin validate` instead.
